# 案例 B 精读：非标门智能制造一体化方案

> 原始材料：一份含 5 张架构图的完整方案文档（总体架构 / 一码贯通 / 角色权限矩阵 / 两段拆单 / 八周计划）。
> 已剔除企业名、客户名、供应商名、竞品系统名。下文以"本方案"指代。
>
> **案例 A 是"建成之后"的操作手册，案例 B 是"建成之前"的销售方案。**
> 前者给你产品结构，后者给你**价值叙事 + 架构 + 交付节奏**。

---

## 1. 方案的叙事骨架：先把账摆在桌面上

方案开篇不谈功能，先讲**客户最贵的三样东西**：

> 被设计拖长的交期 · 说不清楚的订单成本 · 出了问题查不到的人

然后给出**六项优势**（注意每一项都是"经营语言"，不是"功能语言"）：

| # | 优势 | 一句话机制 | 量化承诺 |
| --- | --- | --- | --- |
| 1 | **非标交期压掉两三周** | 流程由串行改并行：长周期材料先预拆投产，设计只卡装饰段 | 同行约 40 天 → 约 25 天 |
| 2 | **一樘门的三分钟档案** | 把裁板机已有的激光打码**激活成全厂数据主线** | 扫码 3 秒出全生命周期档案；反向查批次几分钟锁定受影响樘/项目并一键冻结 |
| 3 | **工人抢着扫码，因为扫码就是工资单** | 扫一枪，计件明细当天进账 | 月底不再手工统计计件；报工数与裁板数/包装数自动交叉核对，异常自动预警 |
| 4 | **订单赚不赚钱，接单当天就有底** | 标准成本下单当天算出；实际成本实时归集 | 亏损单提前亮红灯；发货**齐套校验**硬闸门 |
| 5 | **客户问进度，销售一秒回答** | 订单详情一页看全（设计到第几版/卡在哪道工序/何时发货） | 设计确认全程留痕，交付扯皮有账可查；补件小程序一键发起 |
| 6 | **两个月纯开发周期交出主线** | 有**产品化基线**（平台能力现成 + 行业包沉淀），五条开发线并行 | 8 周纯开发；验收认真机不认文档 |

### 1.1 这份叙事里最值得学的三点

**① 每一项优势都换算成了客户的钱或风险。**
"交期短一周往往就是能不能中标的差别"；"拿得出批次台账的厂和拿不出的厂，在政府项目面前不在一条起跑线上"。
——**不讲功能，讲客户的赢单概率、返工损失、资金周转。**

**② 方案的价值锚点是"客户已有的资产"。**
"裁板机的激光打标已经有了，但那个码现在只活在打标机里，打完就完了。"
——**数字化改造升级的最佳切入点，是客户已经投入但没被利用起来的东西。**
（对比案例 A：切入点也可以是已有的 ERP 订单、已有的称重/计米设备。）

**③ 主动说出"两个月是纯开发周期"。**
> "先把口径说清楚：两个月是开发周期，**不包含**集成调试、数据迁移、培训上线这些事。
> 它们安排在开发完成之后，按实际进度和现场情况动态推进，每一步踩实了再走下一步，**不预埋拍脑袋的日期**。"

——**把大承诺拆成"可承诺的部分"和"动态推进的部分"**，是这份方案可信度的来源。

## 2. 总体架构：五层 + 八入口

### 2.1 接入层：八个入口，一个账号走遍

| 入口 | 使用场景 |
| --- | --- |
| PC 管理端 | 办公室 |
| 车间工位机 | 触屏，**戴手套也能按的大按钮** |
| PDA 扫码枪 | 仓管、质检走动扫码 |
| 手机小程序 | 销售、老板、安装工、售后 |
| 客户 / 经销商门户 | 客户看设计稿和进度 |
| 供应商 / 外协门户 | 接单对账 |
| 车间大屏 | 全员可视化 |
| 第三方系统 API | 集成 |

**关键设计**：**账号是同一个**。领导出差用小程序批单、回办公室用 PC 看报表，**看到的是同一份数据**。

> 为什么不是买一套 ERP + 一套 MES + 一套图纸管理拼起来？
> 方案的回答：**"门厂的订单、图纸、生产、质量、库存本来就是一条连续的生意。拆到三套系统里，
> 每家供应商各管一段，接口对不上，数据打架，最后每套都用一半。"**
> 而且明确点出了现状的断层：进销存一套、图纸在个人电脑里、车间在纸上——
> **"系统之间的断层就是信息对不上的根源"**。

### 2.2 业务应用层：一条业务流，从接单到售后

```
CRM+量尺 │ 配置报价 CPQ │ 销售订单 │ 订单设计 │ 图纸管理 PLM │ 计划排产+齐套
采购/委外 │ 生产执行 MES │ 质量管理 QMS │ 仓储 WMS │ 发运/安装/售后 │ 财务(业财一体)
```

**注意这段的排布逻辑 = 生意的先后顺序**（后文提到 PC 端一级菜单也按这个顺序排，
"新员工看菜单顺序就能看懂生意全貌"）。

### 2.3 能力中台层：配好的引擎，不再重复造轮子

| 引擎 | 作用 |
| --- | --- |
| 主数据 MDM | 物料、客商、BOM 的统一来源 |
| 配置器引擎 | 选型时的约束校验与实时报价 |
| BOM / 下料公式引擎 | 拆单、算料、损耗 |
| 标识与追溯中心 | 码的发放、转码、谱系 |
| 3D 轻量化服务 | 图纸/模型可视 |
| 规则引擎 | 可配置的判定逻辑 |
| 集成中台 API 网关 | 与外部系统对接 |
| BI 报表 | 指标体系 |

> **"能力中台层"是这份方案里最具产品化思维的一层。**
> 它把"可复用的平台能力"和"行业业务逻辑"显式分开——
> 对应到本章第 6 节的**"产品化基线 + 行业包"**，这是能在两个月内交付的全部底气。

### 2.4 车间边缘节点层（断网不停产）★

```
码池缓存与本地出码 │ 任务/图纸快照下发 │ 防错校验本地执行 │ 断网报工暂存/恢复补传
```

**方案原话**：产线关键动作**不走云端实时依赖**。边缘节点提前把**码池和任务图纸快照**下发到车间本地，
断网时**本地出码、本地防错校验、本地看图**，报工先存在本地；网络恢复后受控回传；
万一云端和本地记录打架，矛盾进**裁决队列，每条带两侧证据，班组长在线裁决**，
**工人的工时和计件一分不少**。

> **"断网的麻烦留给系统，不甩给工人"** —— 这句话是整个方案里最有分量的一句。
> 它直接对应第 3 节优势三的前提：**让一线愿意用，是数字化的第一性原理。**
> 对比案例 A 的离线队列 / 幂等 / 先到先得：两者是同一思想在不同成熟度的实现。

### 2.5 设备与 IoT 层

```
激光打标机 │ 数控裁板锯 │ CNC/开槽 │ 封边机 │ 热压机 │ 喷涂线 │ 采集网关
```

> 案例 A 的机联连接方式（OpcUa/ModbusTcp/Mqtt/HttpPush/DbPoll）可直接复用到这一层的实现细节。

## 3. 一码贯通：整套系统的骨架

### 3.1 四层码各管一段

| 码 | 管什么 | 生成时机 |
| --- | --- | --- |
| **部件码** | 每块门板的身份证，**贯穿全程不变** | 裁板激光打标时生成 |
| **托盘码** | 喷涂这类**批量工序** | 进喷涂线时绑定，出线逐件认领 |
| **配套包码** | 把一樘门的**全部五金、花件批次**捆在一起 | 配五金时逐件扫批次码建包 |
| **批次码** | 来料 | 收货时建立 |
| **箱码** | 成品发货单元 | 装箱时 |

**核心设计**：**"码上只存身份，信息全在系统里，扫一枪，该调什么调什么。"**

> 这是标识体系设计的第一原则。把码做成**指针**而不是**数据容器**——
> 好处：码的形态可以极简（激光打标/喷码/贴纸都行）、不随业务变化而失效、不怕信息过时。

### 3.2 码要跟着业务走完整条链

```
销售下单 → 设计确认 → 拆单下料 → 裁板打码 → 工序报工 → 检验记录
→ 装配绑定 → 入库装箱 → 扫码发货 → 安装验收 → 售后报修
                  部件码贯穿全程不变
```

### 3.3 转码接力（一个非常真实的工程细节）

**"喷涂高温会把码打糊，所以设计了转码接力：旧码换新码，谱系关系记录在案，追溯链不断。
码被污染扫不出来，工人在工位机上指认补码，系统验证工序进度一致后发新码——
一个坏码堵不住一条产线。"**

> 三个可迁移的工程模式：
> 1. **物理损耗必然发生** → 设计转码机制，而不是要求"码不许坏"。
> 2. **转码必须记谱系** → 追溯链不能断，否则前面所有追溯投入作废。
> 3. **补码要防作弊** → "验证工序进度一致后"才发新码，否则补码就成了绕过防错的漏洞。

### 3.4 正查 + 反查（追溯的两种问法）

- **正查**：扫任意码 → **3 秒**出全生命周期档案（材料批次 / 工艺参数 / 图纸版本 / 责任人 / 检验记录）。
- **反查**：输入材料批次 → **定位受影响的樘、订单、项目 → 一键冻结 → 导出台账**。

> **只有正查的追溯是演示，只有双向的追溯才是能力。**
> "某一批防火锁出了质量通告，把批次号输进去，几分钟锁定受影响的樘和项目"——
> 这才是客户愿意付钱的那个场景（防火门送检、项目验收、质量事故追责）。

## 4. 角色 × 菜单权限矩阵（18 个一级菜单，13 个角色）

### 4.1 角色清单（13 类）

**内部**：
集团管理 · 厂区管理 · 销售（含内勤）· **设计师** · 技术部 · 计划员 · 采购员 ·
车间主任/班组长 · 车间工人 · 质检员 · 仓管员 · 财务 · 安装工/售后

**外部**：客户 / 经销商 · 供应商 / 外协厂

### 4.2 权限矩阵的图例与规律

图例：`绿✓ = 可操作`、`蓝"查" = 只读`、`灰"—" = 不可见（菜单不显示）`、`橙小字 = 限定说明`。

**方案总结的三条规律**：

1. **销售只碰售前和订单**，进不了车间和财务；
2. **设计师只守设计管理**，别处都是只读；
3. **车间一行里只有生产管理是绿色**，其余全部只读或不可见——**"界面越窄，操作越专注"**。

**补充机制**：
- **一人身兼多岗**：一个账号绑定多个角色，**菜单取并集**。
- **限定说明**：如技术部在采购菜单里只做"打样"判定；车间在生产管理里看得到自己的"计件"。
  ——**同一菜单对不同角色可以有不同粒度的可见范围**（与案例 A 的"财务模块按角色细分页签"完全一致）。
- **菜单排布 = 生意顺序**：`销售 → 订单 → 设计 → 技术 → 计划 → 采购 → 生产 → 质量 → 仓储 → 交付 → 财务`。

### 4.3 数据权限：三道锁

| 层级 | 规则 |
| --- | --- |
| **组织 / 厂区隔离** | A 厂的仓管看不到 B 厂的库存；A 厂的会计碰不到 B 厂的账 |
| **集团穿透** | 集团管理层可穿透看全部厂区，但**要单独授权，且全程留痕** |
| **外部单位（第三道锁）** | 供应商/外协登录门户**只能看到发给它的那部分单据** |

**外部协同的四条具体措施（图纸是核心资产）**：

1. 外协在线看图纸**强制叠加动态水印**，账号、时间实时打在图上，**截图可溯源**；
2. **委托工单结算关闭 → 访问权自动收回**；
3. **下载默认关闭**，要下载走按厂按人的授权；
4. **每一次下载都有审计记录**。

> **"图纸是门厂的核心资产，协同不能以泄密为代价。"**
> 把"权限"从"能不能看"扩展到"能不能带走"——这是产业链协同方案必须回答的问题。

## 5. 十三个角色各自的活（按业务流程排列）

| 角色 | 关键设计 |
| --- | --- |
| **销售 / 内勤** | 线索池分客户、量尺单拍照留档、配置器选型实时出价、报价一键转订单；**客户 360 一页看全**；**"销售人员流动，客户资料留在公司，不带不走"** |
| **设计师** | ★ **本方案里"新立起来"的角色**。订单确认**自动派设计任务**，设计师在任务池领活；每一版设计稿、渲染图挂在任务下；客户每轮驳回意见带批注留档；**"哪张图卡了几天、改了几版，看板一目了然，画图瓶颈第一次有了量化依据"**；定稿一键触发装饰补拆和排产放行 |
| **技术部** | 图纸全部进图纸库，版本状态从设计→评审→客户确认→发布作废**全程受控**；**"现场扫部件码看到的一定是正确版本"**；拆单规则、下料公式、BOM 模板**全部版本化管理**——**"老师傅脑子里的经验变成系统里的规则，历史订单永远能按下单当时的公式复现"** |
| **计划员** | 从"到处问"变成"看一屏"：**齐套视图**按订单列出每樘门的门扇/门套/五金包/花件包各自走到哪道工序，缺件标红、一键定位、一键转采购申请；排产板拖拽排产，产能负载实时提示 |
| **采购员** | 被**缺料分析**驱动着干活：需求 − 库存 − 在途 = 缺口；下单后交期跟踪、催货提醒自动到人；来料批次在收货那一刻建立，**追溯链从进厂第一刻接上**；委外件带部件码进出，"在外协多少、回来多少，账是清的" |
| **车间主任 / 班组长** | 盯派工、进度、异常：托盘没解绑、转码漏了、**断网补传起了冲突**，异常清单推到眼前；**月末系统出计件汇总对账单，班组公示后导出供薪酬发放**——"系统不碰发工资，但明细、勾稽、稽核全备" |
| **车间工人** | 只碰工位机，界面大按钮、**一屏一动作**：我的任务、扫码报工、扫码看图、报不良、我的计件；**"校验不过直接拦截并说明原因，想错都错不了"** |
| **质检员** | 挎 PDA 做**四级检验**：来料按批次、**首件换型换色必检**、工序按部件码、成品按产品族；**"首件没确认，这条工序的批量报工被系统死死拦住，批量不良拦在第一道"** |
| **仓管员** | 收货、备料、发货、盘点全在 PDA；**最有行业味的是配套包**：给一樘防火门配五金时逐件扫批次码建包，系统校验规格、等级、认证，**防火门强制校验防火五金认证**；装配工位再一枪绑定，**"樘和全部批次的对应关系，两枪建立"** |
| **财务** | **首版只做"看得清"的部分**：收款计划、应收台账、发票登记。凭证引擎、总账、成本这些"记得准"的重模块**排在首版之后的第一优先迭代** |
| **安装工 / 售后** | 小程序：安装任务、**现场比对**（门洞尺寸和门扇尺寸提前核对，"别到了现场才发现装不上"）、验收电子签字、异常上报；售后扫门上的码，材料/工艺/责任人/保修期全部带出 |
| **外部（客户/供应商/外协）** | 首版：客户走**极简 H5 确认设计稿**；供应商和外协的协同**暂时由采购、计划在系统里代录**，门户按计划在迭代中上线 |

### 5.1 从这张表里提炼的三条角色设计原则

1. **给"最不数字化的角色"设计最简单的界面**。工人的界面是"一屏一动作"，
   因为**推行一套新系统，成败在头一个月的高频操作顺不顺手**。
2. **给"以前没有的角色"造工具**。设计师原本工作在个人电脑和微信里，进度靠问、版本靠文件名、
   客户确认靠口头——**把这个过程搬进系统并量化，就产生了一个新的管理抓手**。
3. **首版允许"代录"**。供应链门户不做完，就让采购/计划在系统里代录外部单据。
   ——**先让数据进系统，再谈协同**，不要为了外部方的不确定性卡住主线。

### 5.2 工作台设计（登录第一眼）

> 每个角色登录，**首页自动装配成他的样子**。
> 销售看到待跟进客户、待确认设计、回款超期提醒；计划员看到交期预警和齐套缺口；
> 车间主任看到今日派工和异常；财务看到待办凭证和超期应收。
> **待办点一下直达单据，预警点一下直达处理界面。**
>
> 用意："**把每个人每天的事装进一屏，把'找功能'变成'点待办'，培训成本和抵触情绪一起降下来。**"

——与案例 A 的"工作台 = 登录即知今日事"完全同构，**这是跨行业的最优实践**。

## 6. 一樘门在系统里走一遍（端到端主流程）

### 6.1 接单与设计：**两段拆单**（方案的核心创新点）

**传统做法（串行）**：订单确认 → **等设计定稿（约 2~3 周，车间无活可干）** → 拆单下料 → 结构生产 → 装饰/发货 → **交期约 45 天**

**本系统（并行）**：订单确认 → **结构预拆 → 板材门芯投产（第 2 天即投产，不等设计）**；
设计任务与生产并行；**设计定稿只触发「装饰补拆」（花件、线条等装饰段）** → 装饰/齐套/发货 → **交期约 25 天**

> **机制**：订单一确认，系统**同时**干两件事：
> ① **结构预拆**——板材门芯这些长周期材料先投产；② **设计任务自动派发**。
> **"设计周期从卡整门交期，变成只卡装饰段交期。"**
>
> **这是"改造升级"最有说服力的范例：不改工艺、不买设备、不加班，
> 只把串行的流程识别出「可解耦的两段」，让它们并行——交期压缩 3 周。**

**配置与报价**：销售在配置器里选型（尺寸、开向、颜色、五金），**约束规则自动校验**，价格实时出来，
量尺单数据直接带进来不用重录；报价确认 → 一键转订单。

**设计确认留痕**：
- 客户说改 → **意见带圈点批注挂在这一版下面**；
- 客户说定了 → **定稿版本锁定**，装饰段补拆自动执行，订单进入可排产；
- 首期由销售代录并截图留痕，之后客户在门户上自己电子签字。

> **"设计师改了几版、客户哪天确认的、确认的是哪一版，记录清清楚楚。
> 交付验收时如果对方说'当时你们给我看的不是这个样子'，调出确认记录，黑白分明。"**

### 6.2 拆单与图纸：版本不再失控

- 拆单结果是一棵 **PBOM 树**：门扇、门套板、筒子板、贴脸线、五金包、花件包，
  **每个节点挂着工艺路线和图纸，双向可跳**。
- **裁板清单自动算出用料和损耗**；弧形、拱形等异形件走专门工作台人工录入，**一样进正常流程**。
- 图纸库按产品族/项目/订单检索；**电子签审在线走**；变更走 **ECN 流程**，
  **影响分析自动列出在制订单、库存成品、已报价配置里有哪些会被波及**。
- 目标：**"图纸版本误用事故的目标是零。"**

### 6.3 计划与采购：缺什么，提前知道

- 排产板拖拽排产，**产能负载和交期冲突实时提示**。
- **樘齐套是排产的第一约束**：一樘门缺任何一个件都装不了、发不了货 →
  **齐套视图把缺口提前暴露在排产阶段，而不是装配前夜**。
- **缺料分析自动算**：`需求 − 库存 − 在途 = 缺口`；**花件的交期单独预警**，
  "因为开模打样的周期常常是定制门交付的关键路径"。
- 缺口一键转采购申请，采购员不用等电话。

### 6.4 车间：扫码、计件、防错

- 工单下达，**自动派工到工位**。
- **报工粒度按工序配置**：裁板单件扫码报工，喷涂线**整托报工**——
  **"不逼喷涂工人逐件点"**（★ 极重要：报工粒度必须匹配工序物理形态）。
- **返工件强制生成返工作业单**，指定插回哪道工序，**返完强制复检**。
- 托盘进喷涂线绑定，出线逐件认领，**未解绑的托盘上异常看板**。
- **数采同步在走**：热压的温度/压力/时间、喷涂的温湿度，**跟着部件码挂进档案**——
  "将来出了质量问题，**不光知道谁做的，还知道当时机器是什么参数**"。

### 6.5 质量：首件拦截，让步留痕

- 四级检验（前面讲过）。
- **检验方案按产品族配置**：医院、学校项目**默认全检加严**，零售抽检——**"宽严有据"**。
- **让步接收走完整流程**：缺陷描述 → 影响评估 → 内部审批 → 客户确认 → 留痕放行。
  "交付时甲方挑刺，调出当时的让步记录，一清二楚。"

### 6.6 仓储与发货：两枪绑定，一道闸门

- **配套包两枪绑定**：一枪逐件扫批次码建包（校验规格/等级/认证），一枪在装配工位绑定樘。
- **发货端**：项目订单**按楼栋、按安装批次配箱**；装箱单把一樘门的门扇、门套、五金包、花件包配齐。
- **发运前强制齐套校验**：**缺一件就拦下，并指出缺的件卡在哪道工序或哪张采购单。**

### 6.7 安装与售后

- 安装工按发货批次接任务，**到现场先做尺寸比对**（门洞 vs 门扇），
  装完**客户电子签字验收**——"**这个签字同时是收尾款的凭证**"。
- 客户扫门上的码报修，档案自动带出，**保修期内还是期外系统直接判断**。

### 6.8 老板与财务看到什么

- **老板手机上有移动看板**：今天全厂接了多少单、产了多少樘、卡在哪个工序、哪些订单交期告急、哪笔款该收了。
- **厂区大屏挂在车间**：当日计划达成、工序在制品分布、齐套缺口滚动播报。
- **跨厂汇总看板**：如果客户是多厂运营，**一并先上只读版**（对应"集团管控"先上只读的策略）。

## 7. 交付方法论：八周纯开发 + 动态推进（本方案最值得抄的部分）

### 7.1 八周节奏

| 周 | 内容 |
| --- | --- |
| **W1** | **蓝图冲刺**：客户四条业务线（销售/技术/车间/仓库）关键用户坐下来把流程**逐条过、逐条签**；同时确认打标机协议、验证旧系统数据能否导出 |
| **W2** | **设计冻结**：之后新需求不再口头往里塞，走正式变更评估 —— **"这是两个月守得住的第一条纪律"** |
| **W3–W4** | 第一轮迭代（五条开发线并行） |
| **W4 末** | **端到端真机演示**：下单 → 打码 → 报工 → 追溯 |
| **W5–W6** | 第二轮迭代 |
| **W6 末** | **全功能真机演示** |
| **W7** | 功能深化 |
| **W8** | 性能优化、交付测试、**以全功能真机演示收口** |

**贯穿纪律**：**每逢双周做一次真机演示，进度偏差当场暴露，不留到最后一周**；
**第四周和第六周两次硬检查点，偏差超阈值就启动范围降级——先保主线，顺延的明说，不静默延期**。

### 7.2 开发完成之后：按周滚动排期

```
集成调试 → 数据迁移 → 分层培训 → 上线试点 → 全工序推广
```

- **数据迁移**：物料、客商、期初库存。
- **三层培训**：管理层（看板解读，两场）／关键用户（全程三天 + 考核）／车间工人（**按工位小班教学**）。
- **上线试点**：**车间先跑三道工序**——选这五道里的三道，覆盖全部关键机制：
  - **裁板** = 打码的起点；
  - **热压** = 验证数采；
  - **喷涂** = 承载全套方案里风险最高的**托盘闭环和转码机制**。
  **"三道跑通，其余工序的推广就是复制。"**
- **上线首月实施团队驻场巡回**；周期**不拍脑袋**，每周按实际进度和现场问题滚动调整。

> **选试点的标准不是"最简单的"，而是"能覆盖全部关键机制的"。**
> 三条里两条高风险（托盘闭环、转码），这是把风险前置的典型做法。

### 7.3 交付范围三层分级（★ 关键商务技巧）

| 层级 | 范围 |
| --- | --- |
| **核心主线（全量交付）** | 系统管理、工作台、基础数据、销售订单、拆单图纸、**生产执行全套**（打码、报工、防错、托盘、转码、计件、返工、冲突裁决）、四级检验、批次仓储、追溯中心、工位机和 PDA |
| **高价值模块（并行交付）** | 线索客户量尺报价、**设计任务最小版**、项目台账、**排产与齐套**、采购委外、发货安装、标准报表首批、**小程序审批和销售端**、审批流设计器、车间大屏 |
| **裁剪版** | 财务先上**收款计划和应收台账**；集团管控先上**跨厂只读看板** |

**明确后移的模块及理由**：

| 后移模块 | 理由 |
| --- | --- |
| 业财全套（凭证、总账、成本、税务） | **开发密度最大、出错直接连着税务**，硬压必然砸质量 |
| 三个外部门户 | 要牵着外部单位的**账号、培训和意愿**走，不确定性最高 |
| 花件专项采购、参数化下料引擎与套料、3D 预览、集团穿透 | 价值需要更长的消化期 |

> **"后移不等于不做，首版里数据接口和菜单位都留好了，迭代直接生长，不推倒重来。"**
> 而且：**"这份后移清单需要在今天的会上得到认可，它就是两个月开发承诺的对价。"**

### 7.4 双方配合清单（把风险变成条款）

**客户方（6 条）**：

1. **关键用户在头两周投入不低于一半工时**，流程签字一周内完成 —— "蓝图每拖一周，开发窗口就少一周"；
2. **物料和客商主数据第五周前清洗完**，计件单价第五周前定稿 —— "数据不齐，试点验证就是失真的"；
3. **打标机的品牌、型号、通信协议第一周确认**，厂商配合联调 —— "这条不通，打码主线直接受冲击"；
4. **旧系统数据的导出能力第一周验证** —— "导不出明细就降级为只迁汇总余额，历史追溯的范围要书面确认接受"；
5. 培训期和试点期**把工人组织到位**；
6. **设计冻结之后认变更纪律**。

**方案方（5 条）**：
1. **五条开发线满编 25~30 人，主力稳定不中途换人**；
2. **打标机这类老设备对接预留 15%~20% 的缓冲**，专职工程师第一周就上；
3. **每逢双周真机演示**；
4. **第四周和第六周两次硬检查点**，偏差超阈值就启动范围降级；
5. **先保主线，顺延的明说，不静默延期**。

> **这份清单是整个知识库里最实用的一页。**
> 它把"两个月"从一个口号变成了一份**双边对价合同**：
> 客户拖延蓝图一周，我们的开发窗口就少一周——**责任可见，期望可管理**。
> 每一项都是**可验证的动词 + 责任人 + 时点**，不是"希望贵司重视"这类空话。

### 7.5 验收：不认文档，认真机

**开发收尾时当场做这几件事**：

1. **新建一张订单，从配置、拆单、裁板清单、打码、报工、检验、入库到扫码出库，全流程在系统里走完**；
2. **随便扫一个部件码，三秒调出全生命周期档案**；
3. **让首件未确认的工序试批量报工，看系统拦不拦**；
4. **让缺件的订单试发货，看闸门拦不拦**；
5. **十三个角色挨个登录，核对各自工作台和菜单跟权限矩阵图是否一致**。

> **"这几条都过，开发阶段就算交卷。"**
> 注意验收项 3、4 是**负面测试**（测"拦不拦得住"），
> 验收项 5 是**逐角色核对**——这三条比任何"功能清单打勾"都更能证明系统真的能用。

### 7.6 上线之后的迭代排队

| 批次 | 内容 | 理由 |
| --- | --- | --- |
| 第一批 | **业财全套 + 客户门户** | 财务记得准、客户体验 |
| 第二批 | **花件专项 + 套料余料** | 交期和材料成本 |
| 第三批 | 3D 与 AR | 营销差异化 |

## 8. "会上要定的事"——把拍板写成清单

**需要客户现场拍板的**：

1. 角色和权限表跟实际组织**对不对得上**，**一人多岗的情况盘出来**；
2. **首版的范围分层和后移清单认不认**；
3. 两个月纯开发计划和双方配合事项认不认，**每项配合定到责任人**；
4. **车间三工序先行的策略接不接受**；
5. **设计冻结后的变更纪律双方确认**；
6. **项目指导委员会的组成**，建议**一把手任主席**，关键用户清单连同投入比例**写进项目章程**。

> **"中小制造企业上系统，成败第一因素不是技术，是一把手的参与度。"**

**需要客户会后核实的**（每项都影响方案取舍）：

当前实际运营的厂区数量和规模（决定跨厂看板上不上）· 打标机品牌型号协议和厂商联系方式 ·
旧系统能导出哪些数据 · 计件工序清单和现行单价 · 外协厂的数量、模式和能力 ·
花件采购的占比和开模周期 · 客户确认设计的现行习惯 · 用企业微信还是钉钉。

> **"前两项建议一周内给出，第一周的蓝图冲刺就等它们。"**
> ——**把调研问题变成有截止日期的行动项，而不是"后续再了解"。**

## 9. 案例 B 小结：这份方案的"可复制骨架"

抛开行业，一份给新企业的智能化改造方案应当包含这 **8 块**：

| # | 板块 | 案例 B 的做法 |
| --- | --- | --- |
| 1 | **痛点账单** | 先讲客户最贵的三样东西，不讲功能 |
| 2 | **价值叙事** | 6 项优势，每项都换算成钱/风险/赢单率 |
| 3 | **总体架构** | 接入层 / 业务应用层 / 能力中台层 / 边缘节点层 / 设备 IoT 层 |
| 4 | **主线设计** | 一个码串起全生命周期 + 正查/反查 + 转码接力 |
| 5 | **角色与权限** | 角色 × 菜单矩阵 + 组织数据隔离 + 外部协同三道锁 |
| 6 | **端到端走一遍** | 拿一张真实订单从头走到尾，把功能串起来 |
| 7 | **交付节奏** | 八周计划 + 双周真机演示 + 硬检查点 + 上线五步 + 范围三层 |
| 8 | **对价与拍板** | 双方配合清单 + 现场拍板事项 + 会后核实事项 |
