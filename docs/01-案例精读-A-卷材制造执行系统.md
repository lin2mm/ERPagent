# 案例 A 精读：卷材制造执行系统（MES）操作手册

> 原始材料：132 页操作手册，覆盖 5 个终端、19 个功能章节、132 页、4 个附录。
> 已剔除企业名、品牌名、人名。下文一律以"本系统"指代。

---

## 1. 一句话定性

本系统是一家**"卷投料"工厂**的制造执行系统。原材料是不同宽度的**钢卷**，经**辊涂线**镀膜成为成品卷，
再经**裁片线**按订单尺寸裁成白板面板，最后入库、发货、收款。

它解决的不是"有没有系统"，而是四句话：

> **管住卷料 · 打通流程 · 看清现场 · 算清成本**

其中**卷料是核心资产**——老板最关心的是卷料的资金占用与周转效率。
这决定了整套系统的设计重心：**一切围绕"卷号"展开**。

---

## 2. 业务模式抽象：为什么"卷"决定了整个系统架构

这是全文最关键的一段，也是行业外壳之下最可迁移的部分。

| 行业特征 | 对系统的硬性要求 |
| --- | --- |
| 一卷可服务多个订单 | 必须有**卷→多订单的分配/预配机制**（裁切排产、拼板方案） |
| 一个订单可消耗多卷 | 必须有**订单→多卷的拆分机制**（工单按卷拆分，一单多卷） |
| 卷料按米数消耗 | 必须有**自动倒扣**：报工即扣减卷料余长 |
| 余料还可以再用 | 必须有**余料状态**，以及**合卷 / 倒卷**等重组操作 |
| 宽度决定能裁什么 | 必须有**拼板/套料算法**（多订单共享一个卷宽） |
| 批次色差敏感 | 必须有**同单同卷**约束（排产软约束之一） |
| 等级只能降不能升 | 必须有**单向降级 + 发货等级匹配校验** |

**推论**：在卷投料模式下，"库存"不是一个数字，而是**一张以卷为单位的、带位置与状态的实物台账**。
所以系统里卷料有**独立的生命周期状态机（17 态）、独立的事件档案（16 类事件）、独立的溯源链**，
而不是塞进普通物料表。

## 3. 五端应用体系：同一个人群切分，决定终端形态

系统按"**不同的人、不同的设备、不同的场景**"设计了五个应用终端 + 一个统一登录端。

| 终端 | 部署设备 | 主要使用者 | 功能定位 | 设计要点 |
| --- | --- | --- | --- | --- |
| 后台管理端 | 内网 PC（≥1440×900） | 生产部长、车间主任、质检员、仓管员、财务、管理员 | 全功能管理中枢：计划、派工、质量、仓储、采购、发货、财务、系统配置 | 左侧菜单 + 顶部工具条 + 内容区；全局搜索（卷号/工单号/订单号） |
| 老板驾驶舱 | PC / 平板 / 大屏（≥1280×800） | 总经理 | **只读**决策视图：经营、生产、质量、在途四大主题 | 口径由后端统一计算，**前端零加工** |
| 工位平板端 | 车间安卓平板 10 寸+（≥1280×800） | 一线工人、生产部长 | 报工、改单、补贴、异常上报、SOP 查阅 | 触控大按钮（≥指甲 3 倍）、一屏一任务、**长按防误触**、单次操作 10 秒内 |
| 车间大屏 | 55 寸+ 大屏，Kiosk 全屏（≥1920×1080） | 全员，**免登录** | 库位地图、今日动向、工单进度、告警滚动 | 零按钮、扫码即定位、自保护 |
| 移动端 PWA | PDA / 手机（5~6 寸） | 调库员（搬运工） | 扫码调拨、领料确认、离线暂存与同步 | 加到主屏幕、离线队列、左滑撤销 |
| 统一登录端 | 任意浏览器 | 全部用户 | 账号密码登录、角色快速登录、**五端跳转与会话接力** | URL 临时携带令牌，落地后自动清除 |

**可迁移的设计原则**：

1. **终端数量 = 场景数量，不是角色数量**。财务和质检都在管理端；工人只在平板；搬运工只在手机。
2. **只读终端要单独做**。驾驶舱强制只读 + 后端统一口径，避免"老板看到的和车间看到的不是一个数"。
3. **面向一线的界面有物理约束**：戴手套 → 大按钮 + 长按；光线差/吵闹 → 颜色语义 + 红屏 + 语音告警；
   站位远 → 平板可切成"看板视图"供班长巡检。
4. **跨端不重复登录**：会话接力用 URL 令牌传递，落地即清除。

## 4. 九类角色与权限边界

| 角色 | 核心职责 | 可用终端 / 登录落点 | 写权限范围 |
| --- | --- | --- | --- |
| 生产部长 | 排产核心：建计划、拆工单、派工、插单/改单、呆滞决策 | 管理端（计划与派工）/ 工位 / 大屏 / 驾驶舱 | 生产计划、派工、卷料、仓储 |
| 车间主任 | 只读监控：产线进度、异常停机、人员效率 | 管理端（工作台）/ 大屏 | 只读为主 |
| 一线工人 | 工位报工、补贴记录、异常上报 | 工位平板 | 报工/补贴/异常（**仅本人工位**） |
| 调库员 | 现场扫码调拨、领料确认 | 移动端（扫码） | 调拨、领料执行 |
| 质检员 | 检验执行、不良判定、等级变迁、客诉处理 | 管理端（质量检测） | 质量模块全部 |
| 仓管员 | 库位管理、出入库、找卷、调拨、盘点、呆滞处理 | 管理端（仓储）/ 大屏 | 卷料、仓储 |
| 财务 | 应收应付、工资汇算、成本、凭证导出 | 管理端（财务） | 财务模块 |
| 总经理 | 决策监控：资金占用、呆滞、进度、成本 | 驾驶舱 | **全系统只读** |
| 系统管理员 | 用户权限、产线、机联设备、ERP 集成、审计 | 全部终端 | 全部 |

**三条值得抄的规则**：

- **角色决定登录落点**：生产部长→计划编排中心、老板→驾驶舱、工人→工位平板。登录即到达工作现场。
- **财务模块按角色细分页签**：总经理看财务概览与报表，生产条线只看成本与工资，财务岗全量。
  同一菜单、不同可见粒度——比"一刀切不可见"更实用。
- **一人一号，操作日志按账号记录且不可删除**；离职停用账号但**保留历史审计**。

```
├ 看板中心    —— 看板导航 / SOP 管理
```

**观察**：这是一个**中等规模 ERP + MES 合体**的功能集。它不需要 SAP 级别的复杂度，
但**把"从接单到收款"的闭环全部覆盖了**。对中小制造企业，这个"覆盖度"比"深度"更重要。

## 6. 端到端流程：12 个环节

| 序 | 环节 | 操作页面 | 责任岗位 | 要点 |
| --- | --- | --- | --- | --- |
| ① | 订单接入 | 销售管理 → 订单管理 | ERP 同步 / 文员 | ERP 订单行同步进入，状态"待规划"，**重复推送自动去重** |
| ② | 创建生产计划 | 计划编排中心 → 订单待规划 | 生产部长 | 选订单行分摊数量建计划；系统按规格**推荐呆滞卷优先消化**；裁片计划依赖辊涂计划 |
| ③ | 拆分工单 | 计划编排中心 / 自动排单 | 生产部长 | 一个计划拆为若干辊涂工单 + 裁片工单，按卷料拆分、支持一单多卷 |
| ④ | 派工 | 派工执行（辊涂/裁片） | 生产部长 | 选产线 + 日期，按工艺与宽度分组；**产能 80% 黄色预警、100% 硬拦截** |
| ⑤ | 领料 | 移动端扫码 / 大屏 | 调库员 | 派工自动生成领料任务，库位蓝色"待领"高亮；扫错红屏告警 |
| ⑥ | 辊涂报工 | 工位平板 → 报工 | 辊涂工 | 录入计米/产出；**机联计数自动比对**，超容差需二次确认；补贴一键记录 |
| ⑦ | 视觉质检 | 质量检测 → 检验执行 | 质检员 / 机联 | 视觉设备数据**按位置区间标记到卷**，供裁片前缺陷规避与改裁决策 |
| ⑧ | 成品卷入库 | 仓储管理 → 入库管理 | 仓管员 | 按等级分区入库；不良卷走**降级入库（A→B/C 单向）**或整卷退货 |
| ⑨ | 裁片排产与拼板 | 拼板方案 / 裁切排产 | 生产部长 | 算法按卷宽/订单/缺陷生成 2~3 个方案，含成材率、接缝数，择优采纳 |
| ⑩ | 裁片报工 | 工位平板 → 报工 | 裁片工 | 计米 + 计片；超产预警，多产部分强制入 A/B/C 库；系统**自动倒扣卷料余长** |
| ⑪ | 白板入库核销 | 自动 | 系统 | **生产入库即自动倒扣核销销售订单**，订单进度实时更新 |
| ⑫ | 发货收款 | 发货管理 / 财务管理 | 仓管员 / 财务 | 发货前校验**物料等级与客户等级匹配**；发货后**自动生成应收** |

**闭环中三个"自动"是精髓**：自动去重、自动倒扣核销、自动生成应收。
凡是"能自动就不要人点"的地方，都是后续 Agent 化的低垂果实。

## 7. 五层单据体系：上层回答"要什么"，下层回答"怎么做"

| 单据层级 | 回答的问题 | 由谁创建 / 维护 | 编号示例 |
| --- | --- | --- | --- |
| 销售订单 | 客户要什么、要多少、何时交 | ERP 同步 / 文员录入 | `SO-xxx` |
| 生产计划 | 做什么、做多少、用哪类卷料 | 生产部长（或自动排单生成草稿） | `PP-xxx` |
| 工单 | 具体怎么做（辊涂/裁片）、用哪些卷 | 生产部长按计划拆分 | `WO-日期-序号` |
| 派工单 | 派给谁、哪条线、什么顺序、哪天做 | 生产部长 | `D日期-序号` |
| 报工记录 | 做了多少、消耗多少、何时做的 | 工人在平板报工 / 机联自动 | `工单号-序号` |

**典型展开链**：客户订单 5000 片 → 辊涂计划（3 个原料卷）→ 辊涂工单 × 2（按日分派）
→ 裁片计划（**依赖**辊涂完工）→ 裁片工单 × 2 → 报工若干。

**两个细节设计**：
- 工单支持**跨日续派**：多次派工的完工量之和自动回写工单。
- 裁片计划通过"**依赖计划**"挂接辊涂计划，**辊涂完工后裁片工单方可派工**——用依赖关系替代人工判断。

## 8. 卷料生命周期状态机（17 态）

```
在途 → 待入库 → 待检验 → 原料可用 → 辊涂中 → 成品待裁
                              ↓
                        裁片中 → 裁片完成 / 余料
                              ↓
                        已合卷 / 已倒卷（归档，扫老卷号自动跳转新卷）
```

附录 B 中给出的枚举值（可直接作为数据库字典）：

| 值 | 状态 | 说明 |
| --- | --- | --- |
| 0 | 待检验 | 入库完善后待来料检验 |
| 1 | 原料可用 | 检验合格，可领用辊涂 |
| 2 | 辊涂中 | 辊涂线在制 |
| 3 | 待裁片 | 成品卷待裁 |
| 4 | 裁片中 | 裁片线在制 |
| 5 | 裁片完成 | 裁切完毕 |
| 6 | 余料 | 剩余可再用卷 |
| 7 / 8 | 呆滞原料 / 呆滞成品 | 超期未用（30/90/180 天分档） |
| 9 | 已发货 | 终态 |
| 10 | 已报废 | 终态 |
| 11 | 在途 | 采购在途虚拟仓 |
| 12 | 不合格 | 检验不合格待处置 |
| 15 | 已退货 | 退货回库可恢复 |
| 16 | 待入库 | 批号已建，信息待完善 |

**配套机制**：
- **事件档案（16 类事件）**：收卷、检验、开卷、完工、缺陷、裁切、合卷、倒卷、分配、发货、报废、
  呆滞、降级、退货、改单、入库完善。任意时点扫码即可还原"这一卷经历了什么"。
- **溯源闭包表**：合卷/倒卷后老标签作废，但系统自动重定向——扫老码提示"该卷已合卷，已跳转新卷号"。
  **现场旧标签残留是真实痛点，闭包表是最省事的解法。**
- **呆滞三档预警**：30 天（黄）/ 90 天（橙）/ 180 天（红）；呆滞卷不得退回原料库混放
  （原库温湿度会加速膜面氧化），走呆滞品仓分区管理，处置路径为优先改裁消化或降级使用。

## 9. 关键控制点（"闸门"）：系统真正的价值所在

这一节是本手册最值钱的部分。**功能可以少做，闸门不能不做**。

### 9.1 派工三大防呆

1. **在途校验**：派工日期不得晚于在途卷**预计到货日**（依赖采购单如实填写的预计到货日期）。
2. **合同月份管控**：8 月订单不能派到 7 月执行。
3. **产能硬拦截**：产线当日产能 **80% 黄色预警、100% 红色并硬性拦截**新派工，超限提交返回明确报错。

> 前两条是"业务规则校验"，第三条是"物理不可能校验"。**第三种闸门（物理不可能）最不会引起争议。**

### 9.2 质量与发货的三道硬闸门

| 闸门 | 规则 | 不通过时 |
| --- | --- | --- |
| **等级匹配发货校验** | 每个客户等级绑定可发物料等级范围（如 VIP 仅可发 A 级） | **直接阻止发货**；确需放行必须走特采审批并留档；发货记录保留**等级快照** |
| **防多产** | 裁片工单按订单数量封顶（订单 5150 片只允许取 5150 片） | 超取系统预警；多产部分**强制按 A/B/C 等级入库** |
| **自动倒扣** | 报工后按消耗量自动扣减卷料余长 | 退库卷重打剩余米数标签；头尾 **1~2 米属正常误差**，超出自动预警 |

### 9.3 等级单向降级

**A→B→C 允许，反向禁止**；降级历史**永久留痕**，供发货校验与成本核算使用。
配套：不良品只有**两条出路——报废或改裁**（改裁走虚拟订单取数），**不做订单变更**；
无订单的非常规尺寸同样走虚拟订单，**保证每一片产出都有单可依、可核算**。

### 9.4 检验体系（四级）

- **报检检验（来料 IQC）**：可从采购到货自动生成报检单；按物料绑定的检验标准带出检验项；
  合格 → 卷料转"原料可用"，不合格 → 转"不合格"进入处置流程；免检物料可直接标记免检完成。
- **混检管理**：多批次/多物料混合场景的专项检验，作为放行参考之一。
- **过程检验**：首检 / 巡检 / 整机 / 包装首巡检；系统校验**工单是否允许开检（开工判定）**，
  判定合格后工单方可继续生产或完工。
- **客户验货**：客户到厂验货全过程，结论（通过/让步/拒收）关联发货放行。

### 9.5 不合格品处置闭环

`申请 → 评审 → 审批 → 关闭`，与卷料放行/特采标记联动，全程留痕。
**让步放行**审批通过后联动卷料"特采"标记，发货校验据此放行。

### 9.6 改单与插单

**改单五类**（工位平板 ≤3 步完成，已报工数据冻结不可改）：

| 类型 | 用途 | 关键规则 |
| --- | --- | --- |
| 换卷 | 在制卷异常需换卷 | 新卷须**同宽度同膜系**，扫码校验，**扫错红屏拦截 + 语音告警** |
| 调量 | 增减工单数量 | 减量不得低于已完工量；增量走补单 |
| 拆单 | 剩余数量拆出新工单 | 新工单与原单保留**父子关联** |
| 撤销 | 订单取消等 | 计划状态同步回退；可"恢复"回到待开工 |
| 修正 | 录入错误更正 | 单工单改单**超 3 次触发告警** |

**插单流程**：提交申请 → 系统评估在制影响 → 审批 → 按优先级插队：
**P0（可中断在制）、P1（插当前之后）、P2（队尾）**。
插单决策链与月度插单统计**永久保留，作为产线稳定性考核依据**。

> 把"插单"从"老板打个电话"变成"有优先级、有审批、有统计的数据"，是很多工厂最抗拒、
> 但管理收益最大的一步。

## 10. 算法与智能化：本案例已经做到的部分

### 10.1 自动排单（软约束加权求解）

引擎按下列软约束加权求解，生成 **2~3 个候选方案**供人工决策——"**机器算、人来定**"：

| 权重项（默认） | 目标 |
| --- | --- |
| 呆滞优先（0.30） | 优先消耗呆滞卷料，降低资金占压 |
| 交期保障（0.30） | 订单按期完工 |
| 调整成本（0.15） | 同工艺、同宽度连续排产，减少换卷换刀 |
| 成材率（0.15） | 提升裁片成材率 |
| 同单同卷（0.10） | 同一订单尽量用同一卷，避免色差 |

**注意**：自动排单**只生成草稿、不做自动派工**——产线、日期与顺序仍由生产部长决定。
权重可配置（抽屉式"权重配置"），支持"重新计算"。

> **这段是 Agent 化的天然接口**：权重配置面板 = Agent 的显式参数；
> "生成 2~3 个候选 + 人工采纳" = Agent 的标准交互范式。

### 10.2 拼板（套料）优化（8 项硬约束）

硬约束：单边宽度固定、缺陷区间规避、呆滞优先、订单优先级、**接缝数 ≤2**、同单同卷避色差、
余料最小化、**成材率 >92%**。

**降级策略**：若方案计算超时或失败，算法**自动降级为贪心策略**（按优先级顺序排布、遇缺陷跳过），
**保证总能给出可用方案，不会阻塞生产**。

> 这条是整个知识库里最重要的工程原则之一：
> **智能模块必须有"永远能返回一个可用结果"的兜底路径**。工厂不能等算法。

### 10.3 视觉质检与缺陷区间标记

视觉设备数据**按位置区间标记到卷**，形成缺陷记录（类型 / 严重度 / 发生位置与长度 / 检测设备与时间 /
处理状态）。裁片车间开卷前可查看缺陷分布，直接决定规避或改裁
（例："跑偏 2 公分区域改裁 42×578 规格"）。

> **缺陷不是一个"合格/不合格"的布尔值，而是一段带位置的区间**——
> 只有做成区间，才能被下游算法真正利用（规避、改裁、套料）。

### 10.4 机联（设备数据接入）

| 配置项 | 说明 |
| --- | --- |
| 设备类型 | 编码器 / IO 模块 / PLC / 视觉检测设备 |
| 连接方式 | **OpcUa / ModbusTcp / Mqtt / HttpPush / DbPoll** |
| 计数类型 | 计米（辊涂）/ 计片（裁片） |
| 实时计数 / 心跳 | 列表实时刷新计数器当前值与心跳时间，异常离线一目了然 |
| **报工容差** | 报工数量与机联计数允许的偏差百分比；超差时工位端弹**软警告二次确认** |

**报工数据来源三态**：`手工(Manual) / 机联自动(Auto) / 机联+人工修正(AutoModified，必填原因)`。

> 这是"人机结合"的教科书示范：**设备提供基准值，人保留修正权，但修正必须留原因**。

## 11. 工程机制清单（看不见但决定可用性）

| 机制 | 实现要点 |
| --- | --- |
| **离线可用** | 工位端断网提交进入离线队列，恢复后自动补传；**幂等设计，不会重复报工** |
| **移动端离线** | PWA 离线队列存 **IndexedDB**，恢复后批量同步；同卷被他人先处理则按"**先到先得**"判定并提示人工确认 |
| **实时推送** | 待办列表与异常计数随业务**实时刷新（SignalR 推送）**，无需手动刷新 |
| **大屏自保护** | Kiosk 模式：60 秒无操作自动隐藏光标、禁用右键与开发者工具、页面心跳异常 **5 秒内自动刷新**恢复 |
| **数据陈旧标记** | 会议看板全部数据 30 秒自动刷新，右上角显示"数据更新时间"与**陈旧状态标记**，避免例会口径争议 |
| **价格快照** | 能耗单价以**快照**方式保留，保证以往账单金额不随调价变化 |
| **字段级审计** | 变更日志记录"谁、何时、把什么字段从什么值改成什么值"，支持按对象类型/操作类型/日期筛选 |
| **不可删审计** | 操作日志记录登录、插单、改单、派工、入库等关键操作（时间/操作人/模块/动作/目标/IP/HTTP 状态），**不可删除** |
| **ERP 同步可靠性** | **事件驱动出站队列（15 秒轮询）＋ 失败指数退避最多 5 次 ＋ 死信可重推 ＋ 每日凌晨自动对账**；字段映射全配置化，ERP 列名变化无需改程序 |
| **ERP 接入双通道** | 官方 OpenApi 网关（推荐）与 ERP 数据库中间表直连；支持手动触发拉取作为兜底 |
| **库存可对账** | 出入库流水记录每一次库存变动（时间/物料/方向/数量/单据号/经办人），是库存对账与追溯的**最终依据** |
| **盘点闭环** | 计划 → 盘点中（录实盘）→ 复盘 → **生成调整单**（自动创建调整入库/出库单），过账后账实一致 |

## 12. 人机界面设计细节（可复制的具体做法）

- **统一颜色语义**（全系统含大屏/平板/移动端一致）：
  `绿 = 正常/可用/合格/完成`，`蓝 = 进行中/动向/待处理`，`黄 = 呆滞 30 天/一般预警`，
  `橙 = 呆滞 90 天/P1 告警`，`红 = 呆滞 180 天/异常阻断`，`灰 = 空库位/停用/已关闭`。
  口诀："**绿正常、蓝在动、黄要防、橙要急、红必停**"。
- **列表页统一骨架**：`筛选条件 + 状态页签（页签上带数量） + 数据表格 + 行操作`。
  **行操作按钮随单据状态动态显示**——草稿才能编辑，已执行只能查看或红冲。
- **弹窗与表单惯例**：必填项红色 `*`；关键操作二次确认；危险操作按钮为红色、部分需主管账号二次验证。
- **工作台 = 登录即知今日事**：欢迎横幅显示"待办数 + 异常数"（可点击下钻）、我的待办列表、
  八个高频快捷入口。**把"找功能"变成"点待办"**。
- **工位端四大按钮配色**：报工（橙）、改单（蓝）、补贴（绿）、异常（红）；
  **长按 0.5 秒**记录高频补贴（换卷、换刀头），**长按 1.5 秒**提交报工（防戴手套误触）。
- **车间大屏**：左侧 KPI + 告警滚动、中部**库位地图**（扫码枪扫卷后对应库位**闪烁定位 3 秒**）、
  右侧工单进度 + 今日动向、底部扫码条。**"扫一下就知道卷在哪"是仓库最朴素也最刚需的需求。**
- **老板驾驶舱**：首屏三个大数字（今日待交付订单数含超期数 / 卷料资金占用含呆滞占比 /
  呆滞库存 90 天以上卷数），点击任一数字下钻明细；顶部告警横幅直达处理。

## 13. 与 ERP 的协作边界（划清系统边界的方法论）

| 业务对象 | 本系统 → ERP | ERP → 本系统 |
| --- | --- | --- |
| 销售订单 | — | 订单行自动同步进入待规划 |
| 生产入库 / 领退料 | 入库、领料、退料单据回写 | — |
| 发货 | 发货确认后回写销售出库 | — |
| 财务 | 凭证按月导出（用友 U8 格式 CSV） | 总账、应付、发票保留在 ERP |
| 采购 | — | 采购订单手动拉取 / 同步 |

**边界声明（原话精神）**：本系统财务模块定位于**业务财务**（应收应付、成本、资金），
**总账、发票、税务仍以 ERP / 财务软件为准**，系统间通过同步与凭证导出衔接。

> **给新企业做方案时，这张表必须逐行填满并让客户签字。**
> 80% 的"系统不好用"投诉，根因是边界没划清、两边都在录同一笔数。
