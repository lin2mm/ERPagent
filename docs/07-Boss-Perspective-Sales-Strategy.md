# 老板视角：吸引力、顾虑、客户筛选与成交要点

> 前六份文档解决"**怎么把系统做出来、怎么交付**"。
> 这一份解决"**老板会不会掏钱、为什么会犹豫、该找谁谈、怎么谈成**"。
>
> 素材来源：两份原始方案 + 它们各自对应的客户类型（卷投料工厂 / 非标定制工厂）。
> 本文的"老板"特指**中小制造企业的一把手**（年营收 5000 万 ~ 10 亿，员工 80 ~ 800 人，
> 企业由创始人或家族实际控制）。

---

## 零、一句话结论

> **老板买的不是系统，是"少赔钱、多接单、不用我天天盯"这三件事。
> 他最大的顾虑不是价格，是"我推不动"。**

由此推出三条反直觉结论，后文展开：

1. **方案的价值不由信息量决定，由"是否命中老板当下最痛的那一件事"决定。**
   两份材料里老板真正会心动的，都不是篇幅最大的部分。
2. **痛点最强的客户不一定是好客户。** 最好的客户是"已经在赚钱、但看到了天花板"的，和"被外因逼着必须做"的。
3. **提高成功率最有效的动作不是把方案做得更漂亮，而是把"客户的第一笔投入和第一次风险"做小。**

## 一、先认清：老板是谁，他为什么买

### 1.1 老板的四个真实动机（按实际出现频率排序）

好消息是：**理性的 ROI 只排第四。** 前三个动机如果不被满足，算得再清楚的账也签不下来。

| 排序 | 动机 | 老板的原话 | 方案该怎么接 |
| --- | --- | --- | --- |
| **1** | **被外因逼的** | "大客户要求全程溯源""投标要资质""明年要报 IPO" | 直接把这份"外部要求"翻译成功能清单，让他知道**不做会丢什么** |
| **2** | **竞争焦虑** | "同行都上了""老张他们厂去年就搞了" | 带他去参观同行；用同规模同行业的案例说话 |
| **3** | **权力焦虑** | "管不动了""人一走事就乱""我说的话到车间就变样" | 系统要给他**穿透力**：手机上看得到、追得到责、不用靠中层转述 |
| **4** | **算得清账** | "这个能省多少钱 / 多久回本" | 用呆滞资金、成材率、工资、能耗这些**可归集到他账上的数字** |

> **推论**：如果一家企业只有第 4 个动机（单纯"觉得该数字化了"），
> 这个单子会拖很久，且上线后没人用。**没有外部压力或竞争焦虑的项目，成功率天然低一档。**

### 1.2 老板的四种决策风格，对应四条说服路径

先判断他是哪一型，再选话术。**用错型，说再多都白说。**

| 类型 | 特征 | 他要什么 | 说服路径 |
| --- | --- | --- | --- |
| **算账型** | 财务报表熟、精于成本 | 数字与回报周期 | 呆滞资金占用、成材率、单订单毛利、应收周转 — 逐项算给他 |
| **感觉型** | 不看表，靠经验与直觉 | 画面与体感 | 带他走车间、看大屏、现场扫码给他看三秒出档案 |
| **权威型** | 信专家、信协会、信证书 | 背书与资质 | 行业标准、专家意见、甲方验收案例、体系认证要求 |
| **从众型** | "别人做了我就做" | 同行动向 | 同规模同行案例 + 参观。**不要跟他讲技术，讲"隔壁那家"** |

多数老板是**"感觉型 + 从众型"的混合体**——这也解释了为什么
**"带他去看一家活案例"的成交率，远高于在会议室讲一小时 PPT。**

### 1.3 老板最深层的两个恐惧

| 恐惧 | 表现 | 后果 |
| --- | --- | --- |
| **怕失败丢面子** | "再让我考虑考虑""我问问同行" | 拖延。他不是在评估方案，是在找一个不会让他丢脸的下台阶 |
| **怕自己推不动** | "我这帮人用不起来" | 拒签。他知道自己公司的执行力有多差，怕花了钱最后还是自己一个人扛 |

> **第 2 个恐惧被严重低估。**
> 很多方案失败在"把风险全推回给客户"：
> 一句"这个要看你们自己怎么用"，在老板耳朵里等于"成了算你的，不成也算你的"。
>
> **反过来说：任何能降低"必须靠老板亲自推"这一点的方案设计，都会显著提高成交率。**

## 二、吸引力评估：老板真正会掏钱的是哪几条

### 2.1 分级评估（★ = 老板视角的吸引力）

**第一级 ★★★★★ —— 老板会为这一条掏钱**

| 内容 | 出处 | 老板视角的翻译 | 为什么强 |
| --- | --- | --- | --- |
| **呆滞库存资金占用分档预警** | 案例 A（30/90/180 天三档） | "仓库里睡着的钱有多少" | **这是现金，不是效率**。老板对看得见的钱最敏感 |
| **交期压缩 3 周** | 案例 B（40 天 → 25 天） | "能多接多少单""竞标敢不敢承诺" | **这是收入，不是省钱**。收入的叙事强度是省钱的三倍 |
| **计件明细当天进工人账** | 案例 B | "工人自己要用，不用我逼" | **直接消灭老板最大的执行焦虑**（见 2.3） |
| **一键反查 + 台账导出** | 案例 B | "招标资格""被追责时拿得出证据" | 这是**准入资格 + 风险保险**，属于"不得不买" |
| **订单毛利下单当天可见** | 案例 B | "我到底赚没赚钱" | 击中老板最深的不安全感。很多老板真的不知道单订单毛利 |
| **发货齐套校验** | 案例 B | "货到工地才发现少件的返工，从此拦在厂里" | **一次事故的损失就能覆盖项目投入**，账算得极清 |
| **等级匹配发货校验** | 案例 A | "好料不再发给差客户" | 直接防止资产被贱卖 |

**第二级 ★★★ —— 加分项，但不构成购买理由**

| 内容 | 老板视角 | 备注 |
| --- | --- | --- |
| 老板驾驶舱（三个大数字） | "掌控感""有面子" | 移动端 + 一眼看懂 = 老板本人会真用。这是给他个人的 |
| 车间大屏 | "客户来了能看" | **被低估的购买动机**。很多老板买它主要是给客户参观用 |
| 手机批单 | "出差也能管" | 与老板个人体验强相关 |
| 应收账龄与自动催办 | "钱收得回来吗" | 财务口径，老板会问但不会因它签约 |
| 供应商合格率排名 | "谁在坑我" | 采购负责人更关心 |

**第三级 ★ —— 老板听不懂，甚至觉得是负担**

下面这些**在技术方案里很重要，但对老板是负分项**。
给老板讲的版本必须把这些**翻译成结果，而不是讲机制**：

| 技术内容 | 老板的真实反应 | 该怎么讲 |
| --- | --- | --- |
| 五端应用体系、8 个入口 | "搞这么复杂" | "一个人一个账号，办公室里用电脑，车间用大按钮平板" |
| 60 个功能页面、13 个菜单组 | "我这帮人记不住" | **不要提页面数**。只说"你的岗位登录后只看到自己那 3~8 个菜单" |
| 状态机 / 事件档案 / 闭包表 | "听不懂，跟我没关系" | "扫一下就知道这一卷经历过什么" |
| 九类角色权限矩阵 | "又给我加管理成本" | "每个人只看到跟自己有关的，界面越窄越不出错" |
| ERP 边界表 / 集成队列 | "行不行得通？" | "跟现在那套系统各管一段，不重复录单" |
| **132 页操作手册** | **"要学这么多？"** | **这本手册不要给老板看**（见第七节） |

### 2.2 一个反直觉的结论

> **两份材料里，老板真正会心动的内容，都不是篇幅最大的部分。**
>
> - 案例 A 的 132 页手册里，能让老板眼前一亮的可能只有**驾驶舱那一页**和**呆滞预警那一节**；
>   剩下 130 页是给生产部长、车间主任、仓管员看的。
> - 案例 B 的六项优势里，老板最可能记住的是**"扫一枪，计件明细当天进他的账"**——
>   因为那解决的正好是他每天头疼的事；而篇幅巨大的架构图与权限矩阵，他大概率是划过去的。
>
> **所以不要用"材料完整度"衡量一次售前是否成功，要用"有没有命中他此刻最痛的那一件事"衡量。**

### 2.3 为什么"工人抢着扫码"这条威力最大

这条单独拿出来说，因为它同时解决了三个层面：

```
对工人：扫一枪，今天干了多少、能拿多少，下班前一目了然
        → 他不再需要被监督，他自己要用这个系统
对中层：月底不用手工统计计件，争议和博弈一起消失
        → 班组长不再需要替系统打工
对老板：车间从黑箱变透明；且他不用亲自去逼工人用系统
        → 系统自己获得了推行的动力
```

> **一条功能，让三个层级都受益，并且把"推行"这件事从老板身上卸下来。
> 这是两份材料里最有杠杆力的一条，也是最应该在第一次见面就讲的那一条。**

### 2.4 两份方案的吸引力结构差异（重要）

| 维度 | 案例 A（MES 操作手册） | 案例 B（一体化方案） |
| --- | --- | --- |
| 叙事主轴 | **成本 / 资产视角**："管住卷料、算清成本" | **收入 / 交付视角**："交期压 3 周、接单有底气、拿项目有证据" |
| 对老板的强度 | 强，但偏"防守" | **更强，偏"进攻"** |
| 原因 | "省钱"叙事天生弱于"赚钱"叙事 | 把账摆在桌面上开场；每项优势换算成钱/天数/赢单率；主动声明承诺口径 |
| 适合见谁 | **生产部长 / 车间主任 / IT 负责人** | **老板 / 总经理** |

> **给老板谈，用案例 B 的叙事结构；谈成了做交付，用案例 A 的机制结构。**
> （这也是 `ppt/` 下两份 PPT 的分工：PPT-02 开场，PPT-01 落地。）

## 三、顾虑清单：老板不签字的六个真实原因

按**阻力强度**排序。**前两条不解决，价格谈都不用谈。**

### 顾虑一 ★★★★★ · "我推不动"

| 老板的话 | 潜台词 |
| --- | --- |
| "我这帮人年龄大、文化低" | 我知道我公司执行力不行 |
| "以前搞过，最后不了了之" | 我怕再来一次，还丢面子 |
| "上了系统是不是还得我自己天天盯" | 我没那个时间 |

**应对话术（按顺序说）**

1. **"先让一线受益，再让一线受约束。"**
   → 计件当天到账、不用再手写台账、不用再挨骂。工人先得好处，再谈约束。
2. **"老板的驾驶舱第一天就能用，而且不增加任何人的工作量。"**
   → 只读、零操作。他本人立刻得利，且不需要求任何人配合。
3. **"不是一次上全厂，先跑三道工序。"**
   → 缩小他心里的"推行半径"。
4. **"断网、异常这些麻烦，系统自己兜，不甩给工人。"**
   → 这句话的分量极重：它证明你不会把麻烦转嫁到最底层，因而降低他"要替你去摆平"的预期。

### 顾虑二 ★★★★★ · 落地风险

| 老板的话 | 潜台词 |
| --- | --- |
| "你们做过我们这个行业吗" | 我不想当小白鼠 |
| "数据这么乱，能用吗" | 我知道我数据一塌糊涂 |
| "做出来跟说的不一样怎么办" | 我被 PPT 忽悠过 |

**应对**

1. **不认文档，认真机。** 把验收方式讲清楚：**当场跑全流程 + 三处负面测试（测"拦不拦得住"）**。
   这一条本身就是最强的销售话术，因为它把不确定性从客户身上挪到了自己身上。
2. **主动说不做什么**（案例 B 的后移清单）。
   **主动减承诺，是建立信任最快的动作。**即使客户不认，他也知道你实在。
3. **双周真机演示。** 让他每两周看到实物，而不是等到最后。
4. **数据迁移的降级预案要书面**：导不出明细就只迁汇总余额，历史追溯范围双方书面确认。
   → 预先承认边界，比事后解释便宜一百倍。

### 顾虑三 ★★★★ · 钱看不清楚

老板不怕贵，**怕算不清总账**。

| 他的问题 | 你必须提前给答案 |
| --- | --- |
| "一共要花多少" | **软件 + 硬件 + 实施 + 培训 + 年维护费**，一次列全 |
| "平板、大屏、扫码枪是不是还要另买" | 硬件清单单独一页，别混在软件报价里 |
| "第二年还要交钱吗" | 年维护占软件金额的比例，明确写 |
| "后面还要加功能吗" | 后移模块的**价格区间**也给一个，别让他有"无底洞"的恐惧 |
| "多久见效" | 给**阶段性可见**的时间点，不是全期 ROI |

> **硬件是可观的第二笔投入，也是最容易被隐瞒、被投诉的地方。**
> 案例 A/B 都涉及工位平板、大屏、PDA、边缘节点、采集网关——这些加起来很可能超过软件本身。
> **第一次见面就把硬件账摆出来，反而建立信任。**

### 顾虑四 ★★★★ · 人的阻力（老板最不想直面的）

| 谁在反对 | 为什么反对 | 他不敢明说的 |
| --- | --- | --- |
| 生产部长 / 车间主任 | 数据透明后，他的"信息差权力"没了 | 老板知道却不想撕破脸 |
| 老会计 / 财务 | 增加工作量、怕账对不上 | 财务可能是老板的亲属 |
| 老师傅 | 经验被写成规则后，议价能力下降 | 老板敬他、也怕他 |
| 外聘 IT / 顾问 | 为了显示存在感，会提一堆技术问题 | 老板分不清谁对 |

**应对**

1. **早期单独见这些人，并且把他们变成"方案的设计参与者"而不是"被通知的对象"。**
   让他们在蓝图上签字——**签过字的人不会拆自己的台**。
2. **给老板一个台阶**：由老板宣布"这是大家一起定的"，而不是"我买了个东西让你们用"。
3. **识别真正的反对者，并在立项前处理掉。** 如果老板不打算处理，**这个单子不要接**。

### 顾虑五 ★★★ · 供应商的长期风险

中小企业最实在的顾虑，很多供应商不愿意提：

| 老板的话 | 本质 |
| --- | --- |
| "你们公司会不会倒，人走了谁管我" | 乙方是小公司，这是最实在的风险 |
| "做完了以后改一点都要钱吗" | 怕被绑定 |
| "数据是我的还是你们的" | 怕被要挟 |
| "来的人是不是拿我练手" | 怕经验不足 |

**应对**

- **团队稳定性写进条款**：核心实施人员不中途换人（案例 B 已明确承诺"主力稳定不中途换人"）。
- **数据与接口归属写清楚**：数据永远属于客户，接口开放，导出不设限。
- **年维护费与响应时效明确**。
- **坦白讲你接不了的**：老板对"敢说自己不做什么"的乙方，信任度反而更高。

### 顾虑六 ★★★ · 决策心理（面子）

| 表现 | 本质 |
| --- | --- |
| "再考虑考虑""我问问同行" | 在找不丢面的下台阶 |
| 反复问同一个问题 | 心里已有答案，在找支持 |
| 突然压价压得很凶 | 想用价格证明自己"没被忽悠" |

**应对**

- **别逼他当场决定，给他"可以对外讲的理由"**：给他一页能拿给股东/家人/管理层看的材料。
- **让他当主角**：方案里体现他自己提出的想法，让他能对内说"这是我定的"。
- **给同行参照**：他要的不是最好，是"跟别人比不吃亏"。

### 老板必问的六个问题（及标准答法）

| # | 他问 | 错误答法 | 正确答法 |
| --- | --- | --- | --- |
| 1 | **多少钱？** | 报一个总价 | 先答**范围**与**分期**："先做这块是 X，全部是 Y，硬件单独列，第二年维护是 Z%" |
| 2 | **多久？** | "大概半年" | 答**第一个可见成果的时间**："第 2 周你就能在手机上看数据，第 8 周跑完全流程真机演示" |
| 3 | **我这帮人用不起来怎么办？** | "培训一下就好" | "**一屏一动作，工人只学自己那一屏；而且先让他扫码就能看到今天挣多少**" |
| 4 | **同行有没有在用？** | 讲技术优势 | **直接安排参观**，最好是同规模同工艺的厂 |
| 5 | **会不会被绑定？** | "不会的" | "**数据归你，接口开放，导出不设限**；核心人员不换人写进条款" |
| 6 | **你们靠谱吗？** | 讲公司历史 | "**分期付款绑里程碑；干不成的话你损失有限**" |

> **第 3 问和第 6 问是真正的分水岭。** 答不好这两问，前面讲得再漂亮都没用。

## 四、适合筛选什么样的企业和老板谈判

### 4.1 企业侧：七条硬条件（缺一条都要慎重）

| # | 条件 | 合格线 | 不满足的后果 |
| --- | --- | --- | --- |
| **E1** | **规模** | 年营收 **5000 万以上**、员工 **80 人以上** | 低于此：管理复杂度不够、预算不够、没人能用系统 |
| | | 上限约 **10 亿 / 800 人** | 高于此：已有 IT 部门和既有系统，决策链变长，你的角色从"方案方"变成"分包商" |
| **E2** | **一把手能拍板** | 股权清晰、创始人或家族实际控制 | 职业经理人、多头决策、家族内斗 → 项目必拖死 |
| **E3** | **有"钱的痛点"** | 能说出**具体事件**：交期被罚过、呆滞压了几百万、质量事故赔过、招标因资质丢过标 | 只说"感觉需要"的，做出来也没人用 |
| **E4** | **有现金流** | 能拿出几十万 ~ 几百万而不影响经营 | 靠赊账、靠贷款做项目的，交付中途大概率烂尾 |
| **E5** | **有外部压力** | 大客户要求溯源 / 招标要求资质 / 合规检查 / 准备资本化 | **这是最强的项目动力**。没有外因的项目成功率低一档 |
| **E6** | **有数据基础** | 至少在用某个进销存 / ERP，有物料编码（哪怕编码很乱） | 完全手工台账的企业，光主数据清洗就能吃掉全部预算 |
| **E7** | **业务稳定** | 不在生死线上、也不在剧烈转型中 | 一边救命一边上系统的，系统是第一个被砍的 |

### 4.2 老板侧：七条画像（这是真正的筛选器）

| # | 特征 | 为什么重要 |
| --- | --- | --- |
| **B1** | **愿意亲自下场** | ★ **最强筛选器**。能把关键用户按在会议室里签字、能参加双周演示的老板，项目成功率是别人几倍 |
| **B2** | **说得清自己的业务与数字** | 能说出瓶颈工序、不良率量级、库存周转。**说不出来 = 他不在现场，项目必败** |
| **B3** | **有"数字化体感"** | 手机用得好、愿意在手机上看数据、用过企业微信/钉钉。**纯拒绝电子设备的不谈** |
| **B4** | **吃过亏且记得住** | 被质量事故、交期罚款、数据作假坑过。痛过的人才会真投入 |
| **B5** | **有扩张野心** | 想接大客户、想扩产、想做品牌。**有扩张欲的老板才愿意为"管理能力"付费**，否则他只为"省钱"付费，预算会压到最低 |
| **B6** | **年龄与精力** | 主力目标 **45~55 岁的创一代**；55 岁+ 若有懂行的二代或职业经理人接棒，也可以 |
| **B7** | **决策快、不拉扯** | 问三个问题就能判断方向，不需要"再看看"。**拉扯型老板会在交付期持续造成变更** |

**关于年龄的经验判断**

```
35–45 岁   最愿意学、最愿意投入时间，但可支配现金有时偏紧
45–55 岁   ★ 主力客户：企业已有规模、问题已经显性化、有预算、还有冲劲
55 岁以上   除非有二代/职业经理人接棒，或曾被某次事故强烈刺激，否则难推动
```

### 4.3 负面清单：这几类客户不要接

> **烂客户比没客户更伤。** 一个烂项目会占掉你半年产能、拖垮现金流、还砸掉口碑。

| # | 特征 | 为什么危险 |
| --- | --- | --- |
| N1 | 老板不在现场，全权交给职业经理人 | 没人为结果负责，做一半没人拍板 |
| N2 | 近 12 个月内刚有一个信息化项目失败 | 除非你明确知道失败原因并能在方案里回应，否则你会背上历史包袱 |
| N3 | 只问"多少钱"，不问"怎么做" | 纯比价，你只是他的压价工具 |
| N4 | 要"先做个小样看看"却不肯投入任何资源 | 试错成本全在你身上 |
| N5 | 老板认为自己什么都懂，要你"按我说的做" | 你不是乙方，你是打字员 |
| N6 | 业务负责人明确反对，而老板不打算处理 | 交付期会持续被拆台 |
| N7 | 数据极度混乱且无人愿意清洗 | 这不是项目，是慈善 |
| N8 | 行业正在衰退 / 企业准备卖掉 | 没有未来收益预期，预算随时冻结 |
| N9 | 家族内斗 / 股权纠纷 | 决策随时推翻 |
| N10 | 老板要你先做完整方案再谈钱 | 大概率是拿你的方案找别家报价 |

### 4.4 客户分层与打法

| 层级 | 特征 | 打法 | 投入 |
| --- | --- | --- | --- |
| **S 级 · 立即投入** | 规模适中（E1 ✓）＋ 老板愿意亲自下场（B1 ✓）＋ 有外部压力（E5 ✓）＋ 有可量化的痛点事件（E3 ✓） | 带同行业活案例参观 → 两周内做个最小可见成果 → 直接谈分期与里程碑 | **全力** |
| **A 级 · 重点培育** | 满足上面四条中的三条 | 先用一个"只读 + 驾驶舱"的小交付建立信任，再谈主线 | 中等，按季度跟进 |
| **B 级 · 保持观察** | 只满足两条 | 定期发行业案例、邀请参加行业活动，等外部压力出现 | 低，批量触达 |
| **C 级 · 放弃** | 命中任一条负面清单 | 礼貌退出 | **零** |

### 4.5 行业特征筛选

| 优先级 | 行业特征 | 原因 |
| --- | --- | --- |
| **最优先** | 多品种小批量 / 非标定制 + 有明确工序 + 原材料占比高 + 有交期压力 + 有追溯要求 | 案例 A、B 都属这类。**管理与追溯的价值密度最高** |
| | 典型：非标门、幕墙、工程配套、医疗器械、汽车零部件、学校/医院家具、消防产品 | 外部合规压力天然存在（E5 免费满足） |

## 五、提高成功率的关键点

### 5.1 售前阶段：十条

| # | 要点 | 为什么 |
| --- | --- | --- |
| **1** | **第一次见面只讲三件事**：一个具体痛点、一个可量化的数字、一个可在两周内验证的小交付 | 讲架构、讲五端、讲 60 个页面 = 直接劝退 |
| **2** | **用"账单"开场，不用功能清单开场** | 案例 B 做对了：先说"你最贵的三样东西"，再说"我给什么" |
| **3** | **带他去看活案例，且要对标同规模同行业** | 老板最信同行，不信供应商 |
| **4** | **给"小承诺"，不给"大承诺"** | 大承诺引发大怀疑；小承诺引发试用 |
| **5** | **主动说出不做什么** | 案例 B 的后移清单是**最强的信任建立动作** |
| **6** | **让老板出人、出时间，不只出钱** | 出过资源的老板才会真投入，才会在内部替你说话 |
| **7** | **识别并处理"反对者"** | 通常不是老板，是生产部长 / 老会计 / IT 负责人。立项前解决，否则交付期爆炸 |
| **8** | **陪老板走一趟车间** | 边走边问，比在会议室讲 1 小时有效 10 倍；而且你会得到他真实的管理盲区 |
| **9** | **讲同行失败案例** | 比讲自己成功案例更有说服力，且能顺势说明"我们怎么避开" |
| **10** | **降低第一次投入**（范围小、周期短、可退出） | 见下文 5.4 |

### 5.2 交付阶段：九条（这才是复购与口碑的来源）

| # | 要点 | 出处 |
| --- | --- | --- |
| **1** | **试点工序选"能覆盖关键机制的"，不是最简单的** | 案例 B：起点工序 / 有数采的工序 / 最复杂的工序 |
| **2** | **双周真机演示** | 案例 B：进度偏差当场暴露，不留到最后一周 |
| **3** | **范围降级机制写进合同** | 案例 B：偏差超阈值就启动降级，先保主线，**顺延的明说** |
| **4** | **先让一线受益，再上约束** | 案例 B：计件当天到账 |
| **5** | **断网 / 异常不甩锅给工人** | 案例 B：边缘节点兜底；冲突进裁决队列，**工时计件一分不少** |
| **6** | **老板的驾驶舱必须第一天就能用** | 他每天看得到，才会持续投入推动力 |
| **7** | **关键用户要考核 + 奖励，不能只压任务** | 案例 B：关键用户清单连同投入比例写进项目章程 |
| **8** | **数据迁移要有降级预案并书面确认** | 案例 B：导不出明细就只迁汇总余额，范围书面接受 |
| **9** | **不承诺做不到的日期** | 案例 B："两个月是纯开发周期，不含集成调试、迁移、培训、上线" |

### 5.3 商业条款设计：五个建议

| # | 条款 | 设计要点 |
| --- | --- | --- |
| 1 | **分期付款绑里程碑** | 蓝图签字 / 真机演示通过 / 试点上线 / 全厂推广，各付一段 |
| 2 | **软件与硬件分开报价** | 避免"后面又加钱"的投诉；硬件也给了客户比价与自采的空间 |
| 3 | **年维护费明确** | 写清占软件金额的比例与响应时效，避免第二年的信任崩塌 |
| 4 | **效果类条款要谨慎** | 可设计"达到某指标则追加奖励"，**不要设计"达不到就退款"** —— 结果受客户配合度影响太大 |
| 5 | **变更管理写进合同** | 设计冻结点 + 变更评估流程。**这是案例 B"两个月守得住的第一条纪律"** |

### 5.4 最有效的一招：把"第一次风险"做小

> 提高成功率，最有效的动作不是把方案做得更漂亮，而是：
>
> ## **让客户的第一笔投入足够小，第一次成果足够快，退出足够容易。**

具体做法（按投入从小到大排列）：

| 步骤 | 投入 | 周期 | 客户可看到的东西 | 你的风险 |
| --- | --- | --- | --- | --- |
| 1 | 半天 | 当场 | 陪他走车间，现场指出 3 个可量化的浪费 | 极低 |
| 2 | 1 周 | 1 周 | 一页《症断书》：痛点 → 数字 → 建议路径 → 投入区间 | 低 |
| 3 | 小 | 2 周 | **只做驾驶舱与报表（只读、零操作）**，让他手机上看真实数据 | 低 |
| 4 | 中 | 6~8 周 | 试点工序真机演示 | 中 |
| 5 | 大 | 数月 | 全厂推广与迭代 | 高 |

> **注意第 3 步的威力：只读、零操作、两周可见。**
> 它不增加任何人工作量，老板立刻得利，且**完全验证了你的数据接入能力**。
> 这是从"听完方案"到"相信你能做"之间最短的路径。

### 5.5 长期：从项目变成关系

| 动作 | 效果 |
| --- | --- |
| 把客户做成**可参观的样板工厂** | 最强的获客渠道；也让客户有面子（顺带满足第 1 节的"竞争焦虑"动机） |
| **老客户转介绍** | 中小企业老板的圈子很小，一个成功案例能带三单 |
| 从"交付项目"变成"年度服务" | 有持续收入，也让客户有持续的责任人 |
| **帮他对外讲故事**（投标材料、验收台账、政府申报） | 老板拿到的是"面子 + 资格"，你会拿到复购与转介绍 |

## 七、一页速查（贴墙上用）

```
老板买的不是系统，是三件事：
  少赔钱（呆滞资金 / 成材率 / 返工）· 多接单（交期 / 资格 / 毛利）· 不用我天天盯（穿透力）

老板最大的顾虑，不是价格，是「我推不动」：
  所以先让一线受益 → 再上约束；驾驶舱第一天可用且零操作；分阶段；异常不甩锅给工人

给老板讲的版本，删掉这些：
  五端应用体系 · 60 个页面 · 状态机 · 闭包表 · 132 页手册

筛选客户看七条：
  规模够（5000万+）· 一把手能拍板 · 有具体痛点事件 · 有现金流
  · 有外部压力 · 有数据基础 · 有扩张野心

最强的两个筛选器：
  ① 老板愿不愿意把关键用户按在会议室里签字
  ② 老板能不能说出自己工厂的瓶颈数字

不接的客户：
  老板不在现场 · 只问价格 · 业务负责人反对而老板不处理 · 数据乱且无人愿清洗

提高成功率最有效的一招：
  把第一次投入做小、第一次成果做快、退出做容易
  —— 只读驾驶舱 + 两周可见，是从"听完方案"到"相信你能做"的最短路径

一句话记住：
  老板信「人」和「同行」，胜过信「方案」。
```
