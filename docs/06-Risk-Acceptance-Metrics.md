# 风险、验收与度量

> 这份文档是项目的"刹车与仪表盘"：**哪些事会让项目失败、怎么验收才算真的成了、怎么衡量到底有没有用。**

---

## 一、风险登记册

### 1.1 顶级风险（来自两个案例的显式声明）

案例 B 直接点明了一句：**"中小制造企业上系统，成败第一因素不是技术，是一把手的参与度。"**
下表把这类"非技术风险"排在前面。

| # | 风险 | 早期信号 | 缓解措施 | 责任方 |
| --- | --- | --- | --- | --- |
| **R1** | **一把手参与度不足** | 会议只派中层参加；决策迟迟不拍板 | 项目主席由一把手担任并写进章程；关键评审要求一把手到场；**每次硬检查点呈报送达一把手本人** | 客户 |
| **R2** | **关键用户工时投入不足** | 流程签字一拖再拖；访谈约不到人 | 头两周投入比例写进章程并公示；**蓝图每拖一周，开发窗口就少一周**（明确后果） | 客户 |
| **R3** | **需求在冻结后继续塞入** | "顺便再加个小功能"；口头变更 | 设计冻结后走**正式变更评估**；变更必须对应"砍掉什么或延后什么" | 双方 |
| **R4** | **老设备协议不通** | 第一周还没拿到设备协议 | **第一周确认品牌/型号/协议**，厂商配合联调；**预留 15%~20% 缓冲**，专职工程师第一周上 | 双方 |
| **R5** | **旧系统数据导不出明细** | 导出样本迟迟给不出来 | 第一周验证导出能力；导不出则**降级为只迁汇总余额**，历史追溯范围**书面确认接受** | 客户 |
| **R6** | **主数据未清洗** | 第 N 周仍有大量重码/空字段 | 主数据清洗定截止日；**数据不齐，试点验证就是失真的** | 客户 |
| **R7** | **计件单价等业务参数未定稿** | 单价表反复修改 | 单价定稿设时点；未定稿则计件模块延后，**不因此卡住主线** | 客户 |
| **R8** | **试点工序选得太简单** | 选了最没风险的工序 | 试点三工序必须**覆盖全部关键机制**（标识起点 / 数采 / 最高风险机制） | 双方 |
| **R9** | **一线抵触** | 报工改成月底补录；工位端日活低 | **先让一线受益**（计件当天可见 / 免得手写台账）；报工粒度匹配工序；**断网/异常不甩锅给工人**（离线队列 + 幂等 + 冲突待人工确认）；培训按工位小班 | 双方 |
| **R10** | **静默延期** | 进度汇报含糊；演示一再推迟 | **双周真机演示**；**W4/W6 两个硬检查点**；偏差超阈值启动范围降级，**顺延的明说** | 方案方 |
| **R11** | **首版范围膨胀** | 后移清单迟迟不认 | **后移清单当场认可**，并声明"它就是工期承诺的对价"；后移模块的**数据接口和菜单位先留好** | 双方 |
| **R12** | **系统边界不清，双方重复录单** | 同一笔数在两个系统各录一遍 | **边界表逐行签字**；财务定位为业务财务，总账/税务以既有系统为准；凭证按月导出衔接 | 双方 |
| **R13** | **账实不符无法归因** | 上线后库存对不上 | 迁移后**冻结期初基线快照**；出入库流水记录每一次变动（时间/方向/数量/单据号/经办人）作为最终依据；盘点走"计划→实盘→复盘→生成调整单"闭环 | 方案方 |
| **R14** | **闸门被抱怨太死** | 业务部门要求放宽校验 | 闸门有**书面确认 + 出路设计**（走审批留档）；**物理不可能类闸门**（产能上限）优先，管理规则类闸门需老板背书 | 双方 |

### 1.2 技术风险

| # | 风险 | 缓解措施（来自案例的具体做法） |
| --- | --- | --- |
| T1 | 车间网络不稳定导致停线 | **离线队列 + 幂等提交 + 恢复后自动补传**；PWA 离线队列存本地（IndexedDB）；重资产场景上**车间边缘节点**（本地出码/防错/看图） |
| T2 | 冲突操作（同一对象被两人同时处理） | **先到先得**判定；冲突标记**待人工确认**；边缘节点冲突进**裁决队列，每条带两侧证据** |
| T3 | 智能模块卡住生产 | **算法必须有降级路径**（超时降级为贪心，"保证总能给出可用方案，不阻塞生产"） |
| T4 | 设备计数与人工报工不一致 | 走**软警告二次确认**（显示偏差百分比与合计），不硬拦截；容差由管理员配置；数据来源三态留痕（`Manual / Auto / AutoModified`，修正必填原因） |
| T5 | 标识物理损坏（高温/污染） | **转码接力**：旧码换新码 + 谱系记录；现场指认补码需**校验工序进度一致**后才发新码 |
| T6 | 标识分裂/合并后旧标签残留 | **溯源闭包表自动重定向**，扫老码提示"已合卷，已跳转新卷号" |
| T7 | 集成同步丢失/重复 | 出站队列 + 指数退避（最多 5 次）+ 死信可重推 + 每日自动对账 + 字段映射配置化 |
| T8 | 大屏长期无人值守崩溃 | Kiosk 自保护：无操作自动隐藏光标、禁右键与开发者工具、**心跳异常 5 秒内自动刷新**；显示"数据时点/陈旧标记" |
| T9 | 报表口径不一致（例会吵架） | **口径由后端统一计算，前端零加工**；看板标注数据更新时间；驾驶舱强制只读 |
| T10 | 主数据被随意改动 | **字段级变更日志（Before/After）**；操作日志不可删除 |
| T11 | 价格/汇率/单价调整影响历史 | **价格快照**机制（历史账单金额不随调价变化） |

### 1.3 Agent 特有的风险

| # | 风险 | 缓解措施 |
| --- | --- | --- |
| G1 | **Agent 绕过闸门** | 写操作**只走既有业务 API**，禁止直连数据库；闸门在服务层，Agent 无路可绕；负面测试必测"越权" |
| G2 | **Agent 修改冻结数据** | 已报工/已审核数据**只读**；修正走改单/红冲流程（案例 A：已报工数据冻结不可改） |
| G3 | **幻觉编造事实** | 强制 `evidence` 字段；数据缺失时**必须说"缺数据"**；关键结论必须可追溯到单据或规则 |
| G4 | **提示注入**（工单备注/客户留言里藏指令） | 外部文本一律视为**不可信输入**；工具白名单；不允许据文本内容越权调用 |
| G5 | **Agent 对外乱说话** | **禁止直接对外发送消息**；对外口径一律由人发出 |
| G6 | **Agent 无人监督地闭环** | 权限分级：只读 → 草稿 → 闭环；**每波升级需重新验收**；干跑模式先行 |
| G7 | **Agent 故障导致业务停摆** | 必须有降级：Agent 不可用时，原有人工流程完全可用 |
| G8 | **Agent 参与利益分配** | **绝对不做**（工资、单价、罚款）；只提供明细与勾稽依据（案例 B："系统不碰发工资"） |
| G9 | **Agent 输出被当成"系统判定"** | 输出统一标注"建议/候选"，与规则裁决结果在界面上**视觉区分** |
| G10 | **无法审计 Agent 行为** | 以**虚拟账号**接入；操作日志记录操作人（虚拟）/动作/目标/时点；不可删除 |

## 二、验收：三层验收体系

### 2.1 第一层 · 开发阶段验收（不认文档，认真机）

**时间**：W8 收尾。**形式**：当场在真机、真数据上操作。

```
□ 全流程走通：新建订单 → 计划 → 工单 → 派工 → 报工 → 检验 → 入库 → 出库/发货
□ 追溯验证：扫任意主线标识，3 秒调出全生命周期档案（含材料批次/工艺参数/图纸版本/责任人）
□ 负面测试 1：前置条件未确认时试批量报工 → 系统拦截
□ 负面测试 2：不满足齐套/等级条件时试发货 → 闸门拦截并给出原因与出路
□ 负面测试 3：产能超限时试派工 → 硬拦截，报错信息明确
□ 负面测试 4：换料时不满足匹配规则（同宽度同膜系等）→ 红屏拦截
□ 权限核对：全部角色逐个登录，工作台与菜单与权限矩阵**逐一比对一致**
□ 离线验证：断网状态下完成一次报工/扫码，恢复后**自动补传且不重复**
□ 集成验证：一次业务回写既有系统成功；制造一次失败，验证重试与死信重推
□ 审计验证：操作日志可按人/模块/时间筛选；字段级变更留痕
```

> **通过标准**：以上**全部通过**，开发阶段即交卷。
> 注意其中四项是**负面测试**——它们证明的不是"功能有没有"，而是"**管不管得住**"。

### 2.2 第二层 · 上线阶段验收（三工序试点）

```
□ 三道工序连续两周：数据完整（无漏报）、及时（当天录）、可对账（与实物一致）
□ 一线使用率达标：工位端/移动端日活 ≥ 目标；单次报工耗时 ≤ 目标
□ 闸门命中报告：拦截次数与原因分布已有统计，且原因可解释
□ 与既有系统的对账：连续 5 个工作日无未解释差异
□ 期初基线：已冻结并有客户签字
□ 异常处理：现场异常上报 → 管理端处置 → 关闭，跑通过完整闭环
```

### 2.3 第三层 · Agent 验收（每波重新验收）

```
□ 权限声明明确：只读 / 草稿 / 闭环
□ 零直连数据库写入；全部写操作走既有 API
□ 虚拟账号 + 不可删审计
□ 幂等键实现；重试不产生重复单据
□ 降级路径可用：关掉 Agent，原流程可用
□ 输出含 data_as_of 与 evidence
□ 决策类输出为 ≥2 个候选方案，并附风险提示
□ 干跑模式已验证，diff 可读
□ 负面测试通过：不越权、不编数据、不绕闸门、不对外发消息、不碰分配
□ 口径与驾驶舱/报表同源
```

## 三、度量体系

### 3.1 经营结果指标（老板关心的）

| 指标 | 定义 | 来源案例 |
| --- | --- | --- |
| **交期达成率** | 按承诺交期完成 / 总订单 | 案例 B 优势一（交期 40 天 → 25 天） |
| **平均交付周期** | 下单到发货的天数（分标品/非标） | 同上 |
| **成材率 / 材料利用率** | 产出 / 投入（按重量或面积） | 案例 A（拼板约束"成材率 >92%"） |
| **呆滞资金占用** | 90/180 天以上呆滞物料的金额 | 案例 A（驾驶舱三大数字之一） |
| **库存周转天数** | 平均库存 / 日均出库 | 案例 A（"老板最关心卷料的资金占用与周转效率"） |
| **订单毛利准确率** | 下单时预估毛利 vs 结案实际毛利的偏差 | 案例 B 优势四（标准成本下单当天算出） |
| **应收账款周转天数** | 平均回款周期 | 案例 A 账龄分析（30/60/90/180 天） |
| **单起质量事故追溯耗时** | 从发现问题到锁定受影响范围的时间 | 案例 B（目标：分钟级） |
| **返工/报废率** | 返工工时占比 / 报废金额占比 | 两案例的降级与报废流程 |

### 3.2 运营过程指标（管理层关心的）

| 指标 | 定义 | 对应能力 |
| --- | --- | --- |
| **计划达成率** | 实际产量 / 计划产量（分档：<60% 红 / 60~90% 橙 / >90% 绿） | 会议看板标准指标 |
| **产能利用率** | 各产线日占用 / 日产能上限（**80% 黄预警、100% 硬拦截**） | 派工校验 |
| **异常响应/处置时长** | 从上报到关闭的时长（按类型分） | 异常聚合 |
| **插单频次 / 插单影响** | 月度插单数与其导致的延期量 | 案例 A（**插单决策链永久保留，作为产线稳定性 KPI**） |
| **质检一次合格率 / 供应商合格率** | 按批次统计，供应商排名 | 质量监控 |
| **齐套缺口提前暴露天数** | 缺口首次被发现的时点距交期的天数 | 案例 B 齐套视图 |
| **设备非计划停机时长** | 按设备统计 | 设备维护 + 机联心跳 |

### 3.3 系统使用指标（项目组关心的）

| 指标 | 目标方向 | 说明 |
| --- | --- | --- |
| **数据及时率** | ↑ | 当天录入的业务量占比；**低于 80% 说明界面或流程有问题** |
| **工位端/移动端日活** | ↑ | 一线真实使用情况 |
| **单次操作耗时** | ↓ | 案例 A 目标"单次操作 10 秒内完成" |
| **闸门拦截次数与原因分布** | 观察 | 拦截多说明规则在生效；原因变化说明业务在变 |
| **手工调整率** | ↓ | 需要人工干预的比例（如手工改单、手工调库存） |
| **离线队列长度** | ↓ | 车间网络健康度的代理指标 |

### 3.4 Agent 专项指标

| 类别 | 指标 | 说明 |
| --- | --- | --- |
| 质量 | 幻觉率 · **引用准确率** · 方案可行性（被判不可行的比例） | 引用准确率最关键：错了要能查出来 |
| 采纳 | 建议采纳率 · 候选方案采纳分布 · **否决理由分布** | 总是选第一个 = 候选无差异或人没在看；否决理由是**最宝贵的训练信号** |
| 效率 | 决策耗时下降 · 待办转化率 · 覆盖岗位数 | 待办转化率低 = 推送时机或对象错了 |
| 效果 | 与"上 Agent 前"同期对比：交期/成材率/呆滞/处置时长/回款周期 | **必须做对照**，否则无法归因 |
| 安全 | 越权尝试次数 · 被护栏拦截次数 · 干跑 diff 采纳率 | 越权尝试 ≠ 事故，但必须全部被拦截 |

## 四、度量数据的采集方式（别搞成手工填表）

| 方式 | 适用 | 注意事项 |
| --- | --- | --- |
| **系统内自动统计**（首选） | 所有业务过程指标 | 口径由后端统一计算；**看板必须标注数据时点** |
| **事件日志派生** | 响应时长、处置时长、追溯耗时 | 依赖事件档案，所以事件档案要先做 |
| **对照实验** | Agent 效果 | 选同类型的订单/工序分组对比，或与上线前的同期对比 |
| **工位端埋点** | 操作耗时、失败率 | 注意不要采集个人绩效性质的细粒度数据（会引起抵触） |
| **季度回访** | 主观满意度、"最烦的一件事" | 必须**逐条回复**，改不了的说明原因 |

> **原则：能自动采集就不要手工填。** 一旦要人手工填报表，数据质量会在一周内崩掉。

## 五、上线后复盘（三个时点）

### 5.1 上线 +1 个月 · 看"能不能用"

```
□ 数据及时率 ≥ 目标？         □ 一线日活达标？
□ 有没有"月底补录"现象？        □ 卡点 Top3 是什么？（列出并排优先级）
□ 闸门有没有误拦？有没有人绕过去了？（绕过去说明闸门设计有问题）
□ 培训遗漏了哪些岗位/动作？
```

### 5.2 上线 +3 个月 · 看"有没有用"

```
□ 经营指标 vs 上线前基线（交期/成材率/呆滞/回款）
□ 过程指标趋势（计划达成率/异常处置时长/齐套提前暴露天数）
□ 后移模块的第一批是否已排期启动
□ 数据治理例行清单是否在跑
□ 一线"最烦的一件事"收集到的 Top3 是否已解决
```

### 5.3 上线 +6 个月 · 看"能不能自己长"

```
□ 客户业务人员能否自主配置（审批流、检验标准、权限、看板）
□ 是否还有乙方驻场依赖？哪些必须由乙方做，为什么？
□ Agent 四波走到哪一波？前提检查是否通过？
□ 否决理由是否已转成规则/权重调整？（这是 Agent 能不能自我进化的标志）
□ 下一阶段的三个业务目标是什么？（不是功能目标，是业务目标）
```

## 六、一句话版本的风险与验收（贴墙上用）

```
风险不在技术，在三件事：
  一把手的参与度、关键用户头两周的工时、冻结后的变更纪律。

工期不在排期表，在四个动作：
  双周真机演示、两个硬检查点、超阈值就降级、顺延的明说。

验收不看文档，看六个动作：
  全流程真机走通、扫码三秒出档案、三处闸门拦不拦、全部角色核对权限。

成效不在功能清单，在九个数字：
  交期达成率、平均交付周期、成材率、呆滞金额、库存周转、毛利准确率、
  应收周转、追溯耗时、返工报废率。
```
