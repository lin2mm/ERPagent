# 模板 05 · 双方配合清单与里程碑

> 用法：阶段 3 产出，**在会议上当场确认，每项定责任人 + 时点**。
> 这份清单是把"激进工期"变成"可承诺工期"的唯一办法。

---

## 二、里程碑与硬检查点

| 里程碑 | 时点 | 交付物 | 检查点 | 不达标动作 |
| --- | --- | --- | --- | --- |
| M1 蓝图冲刺完成 | W1 末 | 流程签字 + 七道必答题答卷 | ☐ | 顺延，开发窗口等量减少 |
| M2 **设计冻结** | W2 末 | 冻结确认书 | **硬门** | 不冻结不开工 |
| M3 第一轮迭代完成 | W4 末 | **端到端真机演示** | **硬检查点** | 偏差超阈值 → 范围降级 |
| M4 第二轮迭代完成 | W6 末 | **全功能真机演示** | **硬检查点** | 偏差超阈值 → 范围降级 |
| M5 功能深化完成 | W7 末 | 交付测试报告 | ☐ | |
| M6 **开发收尾** | W8 末 | 全功能真机演示收口 + 验收清单通过 | **硬门** | |
| M7 集成调试完成 | 开发后按周滚动 | 集成调试报告 | ☐ | |
| M8 数据迁移完成 | 同上 | 核对表 + 期初基线签字 | ☐ | |
| M9 培训完成 | 同上 | 考核结果 | ☐ | |
| M10 三工序试点上线 | 同上 | 试点报告 | ☐ | |
| M11 全工序推广完成 | 同上 | 推广报告 | ☐ | |
| M12 Agent 四波 | 见 Agent 方案 | 各波度量报告 | 每波重新验收 | 不达标不升级权限 |

**偏差阈值**（需双方约定具体数值）

```
功能偏差超过 ____%      或  关键路径阻塞超过 ____ 天
→ 触发范围降级：先保核心主线，顺延项明确列出并双方确认
→ 原则：顺延的明说，不静默延期
```

## 五、需现场拍板的事项

| # | 事项 | 建议 | 拍板人 | 结论 |
| --- | --- | --- | --- | --- |
| 1 | 角色和权限表与实际组织是否对得上；一人多岗盘清楚 | 部门负责人逐一核对签字 | | |
| 2 | 首版范围分层与后移清单认不认 | 认可，作为工期对价 | | |
| 3 | 开发计划与双方配合事项认不认；每项定责任人 | 当场定到人 | | |
| 4 | 试点工序先行的策略接不接受 | 三工序覆盖全部关键机制 | | |
| 5 | 设计冻结后的变更纪律 | 双方确认 | | |
| 6 | 项目指导委员会组成 | **一把手任主席**；关键用户清单连同投入比例写进章程 | | |

## 六、需会后核实的事项（带截止日期）

| # | 事项 | 为什么要 | 截止 | 责任人 | 完成 |
| --- | --- | --- | --- | --- | --- |
| 1 | 实际运营的厂区数量与规模 | 决定跨厂看板本期上不上 | | | ☐ |
| 2 | 设备品牌型号协议 + 厂商联系方式 | 第一周蓝图冲刺就等它 | | | ☐ |
| 3 | 旧系统能导出哪些数据 | 决定迁移范围与历史追溯深度 | | | ☐ |
| 4 | 计件工序清单与现行单价 | 决定计件模块能否上首版 | | | ☐ |
| 5 | 外协厂数量、模式与能力 | 决定门户是自建还是系统内代录 | | | ☐ |
| 6 | 关键件/长周期件的采购占比与周期 | 决定齐套预警的关键路径项 | | | ☐ |
| 7 | 客户确认设计的现行习惯 | 决定首版走电子签还是代录留痕 | | | ☐ |
| 8 | 移动办公平台（企业微信 / 钉钉 / 其他） | 决定小程序与消息通道 | | | ☐ |

> **建议前两项一周内给出** —— 第一周的蓝图冲刺就等它们。

## 七、项目章程要点（写入正式文件）

```
1. 项目名称与目标（业务目标，不是功能目标）
2. 项目主席：____________（一把手）  ← 中小制造企业上系统，成败第一因素不是技术，是一把手的参与度
3. 关键用户名单 + 各自承诺的投入比例
4. 范围：三层清单 + 后移清单（附件）
5. 里程碑与硬检查点（附件）
6. 变更纪律：设计冻结点 = ______；之后走正式变更评估
7. 例会节奏：周会（进度/风险）+ 双周演示（成果）+ 硬检查点（决策）
8. 验收方式：不认文档，认真机；含负面测试
9. 双方配合清单（附件）
10. 争议解决机制与升级路径
```
